**1. 인공지능이란?**

인공지능(AI)은 컴퓨터가 사람처럼 학습, 추론, 판단, 문제 해결, 의사결정 등을 수행할 수 있도록 만드는 기술이다. 간단히 말하면 "데이터나 경험을 바탕으로 학습하고 판단해서 문제를 해결하는 기술"이라고 이해할 수 있다.

**전통적인 프로그래밍**에서는 사람이 규칙을 직접 작성한다.

```python
age = 25

if age >= 19:
    print("성인")
else:
    print("미성년자")
```

```text
입력 데이터 + 사람이 만든 규칙 → 결과
```

**머신러닝**은 데이터를 이용해서 컴퓨터가 규칙을 학습하도록 만드는 방식이다. 예를 들어 유방암 진단이라면 종양의 크기·둘레·질감 등 + 실제 악성/양성 여부 데이터를 넣으면, 머신러닝이 악성과 양성을 구분하는 규칙을 스스로 찾아낸다.

```text
[전통적인 프로그래밍]        [머신러닝]
Data + Rule                  Data + Result
     ↓                            ↓
  Computer                Machine Learning
     ↓                            ↓
   Result                   Rule / Model
```

학습된 모델을 이용할 때는 `새로운 데이터 → 학습된 Model → 예측값` 흐름이 된다.

**2. 머신러닝 워크플로우**

```text
수집 → 점검 및 탐색 → 전처리 및 정제 → 모델링 및 훈련 → 평가 → 배포
```

조금 더 자세히 보면:

1. 데이터 수집
2. EDA (데이터 구조/Feature/Target/결측치/분포 확인)
3. Data Preprocessing (Cleaning, Feature Engineering, Encoding, Scaling)
4. Train / Test Split
5. Model 생성
6. Model 학습
7. Prediction
8. Evaluation
9. Hyperparameter 조절
10. 최종 Model 배포

**머신러닝 학습 방법**은 다음 흐름으로 이루어진다.

```text
Input(Feature X) → Model → Prediction ŷ
                              │
                    True Target y와 비교
                              │
                        Loss Function
                              │
                         Loss Score
                              │
                    Learning Algorithm
                              │
                        Parameters 수정
                              │
                            Model
                              │
                            반복
```

**Loss Function**은 실제값(y)과 예측값(ŷ)을 비교해서 모델이 얼마나 틀렸는지 하나의 숫자로 표현한다. Loss가 크면 오차가 크고, Loss가 작으면 오차가 작다는 뜻이다. 머신러닝 모델은 일반적으로 **Loss가 작아지는 방향으로 Parameter를 수정**하면서 학습한다.

---

**3. 머신러닝 종류**

머신러닝은 크게 지도학습 / 비지도학습 / 강화학습으로 나눌 수 있다.

**지도학습(Supervised Learning)**: 정답(Label)이 있는 데이터를 이용하여 학습한다. `Feature + Target → 학습 → 새로운 데이터 예측`.

- **분류(Classification)**: Target이 범주형 데이터인 문제. 악성/양성, 스팸/정상메일, 합격/불합격, 고양이/강아지 등. MNIST 필기체 인식, 스팸 메일 인식, 암 진단 등에 활용.
- **회귀(Regression)**: Target이 연속적인 수치형 데이터인 문제. 집값 예측, 자동차 가격 예측, 매출 예측, 온도 예측 등. 참고로 주가도 수치를 예측한다는 점에서 회귀로 접근할 수 있지만, 실제로는 시간에 따른 흐름이 있는 시계열 데이터라 일반 회귀보다 복잡하다.

```text
내일 비가 오는가? → Yes/No → 분류
내일 강수량은 몇 mm인가? → 14.2 → 회귀
```

**비지도학습(Unsupervised Learning)**: 정답 Label 없이 Feature만 이용해 데이터 안의 패턴을 찾는다. Clustering(비슷한 특징의 데이터를 그룹으로 묶기), 차원 축소, 이상치 탐지 등이 대표적이다.

**강화학습(Reinforcement Learning)**: 행동에 따른 보상(Reward)을 이용해 최적의 행동을 학습한다. `현재 상태 → 행동 선택 → 보상 → 다음 행동 → 반복`. 게임 AI, 로봇 제어, 일부 자율주행 의사결정 등에 사용된다.

---

**4. 머신러닝 기본 용어**

- **Feature**: 독립변수. 모델이 Target을 예측할 때 사용하는 입력 데이터 (= X). 예: 집 면적, 방 개수, 건축연도, 지역
- **Target**: 종속변수. 모델이 최종적으로 구하고 싶은 값 (= Label = y). 예: 집값, 악성/양성
- **Class**: 분류 문제에서 Target이 가질 수 있는 각각의 범주. 고양이/강아지/토끼면 Class는 3개
- **Parameter**: 모델이 학습 과정에서 자동으로 찾아내는 값. `y = wx + b`에서 w, b가 Parameter
- **Hyperparameter**: 사용자가 모델 학습 전에 직접 설정하는 값. Tree의 최대 깊이, KNN의 K, Learning Rate 등
- **Loss**: 정답값과 예측값 사이의 오차. 주로 모델이 학습하는 과정에서 사용
- **Metric(평가지표)**: 모델의 최종 성능을 평가할 때 사용. 분류는 Accuracy/Precision/Recall/F1-score/ROC-AUC, 회귀는 MAE/MSE/RMSE/R² 등

Loss는 학습할 때 모델이 줄이려고 하는 값이고, Metric은 학습된 모델의 성능을 평가하는 값이다. 경우에 따라 같은 계산식을 Loss와 Metric 둘 다로 쓸 수도 있다.

**5. Breast Cancer 데이터로 워크플로우 실습**

**Global Variables 설정**: 모델 학습을 여러 번 진행하면서 공통으로 사용할 설정값을 EasyDict 객체에 저장한다.

```python
import easydict

args = easydict.EasyDict()
args.seed = 42
args.target_col = 'target'
```

일반 Dictionary는 `args['seed']`처럼 사용하지만, EasyDict는 `args.seed`처럼 속성으로 접근할 수 있다.

**Random Seed**를 고정하지 않으면 랜덤 연산 결과가 매번 달라지지만(A, B, C...), 고정하면 동일한 코드와 환경에서 같은 랜덤 결과를 재현하기 쉬워진다(A, A, A...). 핵심은 **같은 조건에서 실험 결과를 재현하기 위해 사용**한다는 것이다.

**1) 데이터 수집**

```python
from sklearn.datasets import load_breast_cancer

data = load_breast_cancer()
dir(data)
```
> ['DESCR', 'data', 'data_module', 'feature_names', 'filename', 'frame', 'target', 'target_names']

`dir()`은 Python 내장 함수로, 해당 객체 안에 어떤 속성이나 메서드가 있는지 이름 목록을 확인할 수 있다. sklearn 데이터가 아니어도 리스트, 문자열, DataFrame 등 어디에나 사용할 수 있다. `data`, `target`, `feature_names` 등이 나오는 이유는 `dir()`이 만든 게 아니라 원래 그 객체 안에 들어있기 때문이다.

```python
data.feature_names  # 총 30개의 Feature
data.target_names   # ['malignant', 'benign']
```

`target_names`는 실제로 `0 → malignant(악성)`, `1 → benign(양성)`으로 저장되어 있다. Class가 두 개이므로 **이진분류** 문제다.

```python
print(data.DESCR)  # 데이터 출처, Feature 설명, 참고 논문 등
```

실제 프로젝트에서도 분석 전에 데이터 정의서와 컬럼 설명을 확인하는 과정이 중요하다.

**2) 점검 및 탐색 (EDA)**

```python
df = pd.DataFrame(data.data, columns=data.feature_names)
df[args.target_col] = data.target

df.shape   # (569, 31)
df.info()  # 결측치 없음, Feature는 float64, Target은 int64
df.head()
df.describe()
```

Target이 `int64`라고 해서 연속형 수치 데이터인 건 아니다. 0/1이라는 범주를 의미하므로 실제로는 범주형 Target이다. Target 평균이 0.627417이라는 건 1의 비율이 약 62.7%라는 의미로 해석할 수도 있지만, 분류 데이터에서는 다음 코드가 더 직접적이다.

```python
df['target'].value_counts()
df['target'].value_counts(normalize=True)
```

**3) 전처리 및 정제**

대표적인 전처리 작업: Cleaning(결측치 제거/치환), Feature Engineering(새 Feature 생성), Encoding(문자/범주형 → 숫자), Scaling(숫자 크기/단위 통일).

```python
df.isnull().sum().sum()  # 0, 결측치 없음
```

**학습/평가 데이터셋 나누기**:

```python
from sklearn.model_selection import train_test_split

train, test = train_test_split(df, random_state=args.seed)
train.shape, test.shape  # ((426, 31), (143, 31))
```

`test_size`를 지정하지 않으면 기본 Test 비율은 25%다. 실제 예측할 때는 Feature만 필요하고(`Feature → Model → Prediction`), Target은 Train에서는 학습할 때 정답, Test에서는 평가할 때 정답으로 사용한다.

```python
x_train = train.drop(args.target_col, axis=1)
y_train = train[args.target_col]
x_test = test.drop(args.target_col, axis=1)
y_test = test[args.target_col]

x_train.shape, y_train.shape, x_test.shape, y_test.shape
# ((426, 30), (426,), (143, 30), (143,))
```

여기서 확인해야 할 것: `x_train`의 Column 수 = `x_test`의 Column 수, `x_train`의 Row 수 = `y_train`의 Row 수여야 한다. Feature 한 Row마다 정답 하나가 대응해야 하기 때문이다.

**4) 모델링 및 훈련**

진행 과정: 알고리즘 선택 → Hyperparameter 설정 → Model 생성 → Model 학습.

```python
from sklearn.linear_model import LogisticRegression

model = LogisticRegression(random_state=args.seed)
```

`LogisticRegression`은 이름에 Regression이 들어가지만 실제로는 **분류 모델**이다(LinearRegression=회귀, LogisticRegression=분류). 이진분류뿐 아니라 다중분류에도 사용할 수 있다.

모델 객체를 만들었다고 바로 예측할 수 있는 건 아니고, 반드시 학습을 먼저 실행해야 한다.

```python
model.fit(x_train, y_train)
```

```text
모델 생성 → model.fit() → 모델 학습 → model.predict() → 예측
```

**5) 평가**

```python
from sklearn.metrics import accuracy_score

y_pred = model.predict(x_test)
accuracy_score(y_test, y_pred)
```
> 0.972027972027972 (약 97.2%)

Accuracy = 맞춘 데이터 수 / 전체 데이터 수. 다만 Accuracy만 보면 안 되는 이유가 있다. 예를 들어 정상 99명, 암 1명인 데이터에서 모델이 전부 "정상"이라고 예측하면 Accuracy는 99%지만 실제 암 환자는 한 명도 찾지 못한다. 그래서 분류에서는 Precision, Recall, F1-score, Confusion Matrix, ROC-AUC도 같이 확인한다.

**6. Titanic 데이터 전처리**

```python
import seaborn as sns

df = sns.load_dataset('titanic')
df.shape  # (891, 15)
```

**같은 의미의 데이터 삭제**: `pclass↔class`, `embarked↔embark_town`, `survived↔alive`처럼 중복되는 컬럼이 있다. 특히 `survived`와 `alive`는 사실상 동일한 정답 정보라, Target을 `survived`로 쓸 때 `alive`가 Feature에 남아있으면 **Data Leakage**가 발생할 수 있다.

```python
df.drop(['class', 'embark_town', 'alive'], axis=1, inplace=True)
df.shape  # (891, 12)
```

**Train/Test 분리 (8:2)**:

```python
from sklearn.model_selection import train_test_split

seed = 42
train, test = train_test_split(df, random_state=seed, test_size=0.2)
train.shape, test.shape  # (712, 179)
```

8:2 비율이 절대적인 규칙은 아니고 70:30, 75:25 등도 자주 쓰인다. 핵심은 Train은 모델이 충분히 학습할 데이터, Test는 모델이 보지 않은 데이터로 성능을 확인하는 것이다.

**이진분류/다중분류 확인**: `train['survived'].unique()`로 Class 개수를 확인한다. Titanic은 0, 1 두 개이므로 이진분류다.

**EDA — Target 분석**: 분류 문제에서 Target을 확인할 때는 Class가 몇 개인지, 각 Class의 데이터 수와 비율은 어떤지, 특정 Class가 지나치게 적지는 않은지를 본다.

```python
train['survived'].value_counts()
# 0: 444, 1: 268

train['survived'].value_counts() / train.shape[0]
# 0: 약 62.4%, 1: 약 37.6%
```

62:38 정도로는 반드시 심한 불균형(Imbalance)이라고 판단할 필요는 없다. 99:1, 95:5, 90:10처럼 특정 Class가 매우 적을 때 Class Imbalance 문제가 더 뚜렷해진다. 특정 Class 데이터가 너무 적으면 그 Class의 특징을 충분히 학습하기 어려울 수 있고, 지나치게 많으면 모델이 많은 Class 위주로 예측할 위험이 있다.

**stratify**: Train/Test 분리 시 Class 비율을 유지하고 싶다면 `stratify` 옵션을 사용한다.

```python
train, test = train_test_split(
    df, random_state=seed, test_size=0.2,
    stratify=df['survived']
)
```

**수치형/범주형 데이터 분석**:

```python
train_number = train.select_dtypes(include=np.number)
train_number.describe()

train_str = train.select_dtypes(exclude=np.number)
train_str.describe()
```

`select_dtypes(include=np.number)`는 저장된 dtype만 기준으로 선택하기 때문에 `survived`, `pclass`도 숫자로 선택되지만, 실제 의미는 `survived`=범주형 Target, `pclass`=순서가 있는 범주형이다. 즉 dtype이 항상 실제 데이터의 의미와 같지는 않다. 참고로 `train_str`이라는 이름이지만 실제로는 str뿐 아니라 bool, category도 포함된 비수치형 데이터에 가깝다.

**Cleaning**:

```python
(train.isnull().sum() / len(train)).sort_values(ascending=False)
# deck 0.778, age 0.197, embarked 0.003
```

수치형은 평균으로, 범주형은 최빈값으로 처리한다.

```python
for df_tmp in [train, test]:
    null_cols = df_tmp.isnull().sum()
    null_cols = null_cols[null_cols > 0].index.to_list()

    for col in null_cols:
        try:
            df_tmp[col] = df_tmp[col].fillna(df_tmp[col].mean())
        except:
            df_tmp[col] = df_tmp[col].fillna(df_tmp[col].mode().values[0])
```

다만 이 방식은 실습용으로는 이해하기 쉽지만, `except:`가 모든 오류를 잡아버려서 mean() 실패가 아닌 다른 오류까지 숨길 수 있어 실제 코드에서는 타입을 직접 확인하는 게 더 안전할 수 있다.

**매우 중요한 Data Leakage 포인트**: 위 코드는 Train은 Train 평균으로, Test는 Test 평균으로 각각 결측치를 채운다. 하지만 실전 머신러닝에서는 보통 **Train에서 계산한 전처리 기준을 Test에도 그대로 사용**해야 한다.

```python
age_mean = train['age'].mean()
train['age'] = train['age'].fillna(age_mean)
test['age'] = test['age'].fillna(age_mean)  # Train 평균을 그대로 사용
```

Test 데이터에서 새로운 평균을 계산하면 Test의 정보가 전처리에 사용되는 Data Leakage 문제가 생길 수 있다.

`deck`은 Train 77.8%, Test 74.9%가 결측치라 단순 최빈값 대체는 데이터를 왜곡할 수 있다. 실제로는 deck 삭제, "Unknown" 범주 생성, deck 정보 존재 여부를 새 Feature로 만드는 방법 등도 검토할 수 있다.

**Feature 추출**:

```python
train['family_cnt'] = train.apply(
    lambda row: int(row['sibsp']) + int(row['parch']), axis=1
)
test['family_cnt'] = test.apply(
    lambda row: int(row['sibsp']) + int(row['parch']), axis=1

```

`sibsp`(형제자매/배우자)+`parch`(부모/자녀) = `family_cnt`. 본인까지 포함하려면 `+1`을 더해 `family_size`로 만들 수도 있다. 단순 덧셈이라면 `apply()` 없이 벡터 연산으로도 가능하다.

```python
train['family_cnt'] = train['sibsp'] + train['parch']
test['family_cnt'] = test['sibsp'] + test['parch']
```

범주형 Feature 조합도 만들 수 있다.

```python
train['deck_who'] = train['deck'].astype('str') + "_" + train['who']
test['deck_who'] = test['deck'].astype('str') + "_" + test['who']
```

두 Feature의 조합 자체가 Target과 새로운 관계를 가질 수 있어 이런 Feature를 시도해볼 수 있다.

**7. 범주형 데이터 인코딩**

머신러닝 모델 대부분은 male, female, Southampton 같은 문자열을 그대로 처리하지 못하므로 숫자로 변환해야 한다.

- **One-Hot Encoding**: 범주 하나당 새로운 컬럼을 만든다. `who_man`, `who_woman`, `who_child`처럼. 순서가 없는 명목형 범주에 많이 사용한다.
- **Mean Encoding**: 각 범주에 해당하는 Target의 평균 등으로 숫자로 바꾼다. Target을 이용하기 때문에 Data Leakage가 발생하기 쉽다.
- **Label Encoding**: 각 범주에 번호를 부여한다 (male→0, female→1). 단, 실제 순서가 없는 범주에 인위적인 순서 관계(0<1<2)가 생길 수 있다.
- **Target Encoding**: 범주마다 해당 범주의 Target 통계값을 계산해 변환한다. 역시 Data Leakage에 특히 주의해야 한다.
- **Ordinal Encoding**: 실제로 순서가 존재하는 범주를 숫자로 바꾼다 (Low→0, Medium→1, High→2).

**인코딩 실습**:

```python
df = sns.load_dataset('titanic')
df.drop(['class', 'embark_town', 'alive'], axis=1, inplace=True)

train, test = train_test_split(df, random_state=seed, test_size=0.2)
```

**전처리 함수를 별도 파일로 분리**: 반복해서 쓸 전처리 코드를 `common/preprocessing.py`로 분리해서 관리한다.

```python
def do_cleaning(train, test):
    print(f"before - train: {train.isnull().sum().sum()}, test: {test.isnull().sum().sum()}")
    for df_tmp in [train, test]:
```

**One-Hot Encoding 실습**: 우선 `who` 컬럼 하나만 해본다.


`fit()`은 Train 데이터에서 어떤 범주가 존재하는지 확인하고 Encoding 규칙을 학습하는 것이고, `transform()`은 그 규칙을 실제 데이터에 적용하는 것이다.

```text
who = [man, man, child, woman]
     ↓ One-Hot Encoding
who_man  who_child  who_woman
   1        0           0
   1        0           0
   0        1           0
   0        0           1
```

Encoding 전 하나의 컬럼은 개념적으로 Vector이고, One-Hot Encoding 후 여러 컬럼이 생기면 Matrix 형태가 된다. 다만 모든 Encoding이 여러 컬럼을 만드는 건 아니고, Label/Ordinal/Target Encoding은 하나의 범주형 Feature를 하나의 숫자 Feature로 변환하기도 한다.


**모든 범주형 컬럼을 반복 처리하는 함수**:

```python
def add_one_hot_encoding(encoder, x_train_str, x_test_str):
    x_train_enc = pd.DataFrame()
    x_test_enc = pd.DataFrame()

    for col in x_train_str.columns:
        encoder.fit(x_train_str[col].astype('category'))

        encoded_col = encoder.transform(x_train_str[col].astype('category'))
        encoded_col_test = encoder.transform(x_test_str[col].astype('category'))

        x_train_enc = pd.concat([x_train_enc, encoded_col], axis=1)
        x_test_enc = pd.concat([x_test_enc, encoded_col_test], axis=1)

    return x_train_enc, x_test_enc
```

```text
Train → fit() + transform()
Test  → transform()만
```

여기가 가장 중요한 부분이다. Test에서 `encoder.fit()`을 다시 실행하면 Test 정보로 새로운 Encoding 규칙을 만드는 셈이 되어 Data Leakage 문제가 발생할 수 있다.

```python
x_train_enc, x_test_enc = add_one_hot_encoding(encoder, x_train_str, x_test_str)
x_train_enc.shape, x_test_enc.shape
# ((712, 19), (179, 19))
```

`sex`, `embarked`, `who`, `adult_male`, `deck`, `alone` 6개 범주형 컬럼이 One-Hot Encoding을 거치며 19개 컬럼으로 늘어난 것이다. 각 범주별로 새 컬럼이 생기기 때문이다.

**8. fit/transform 패턴**

앞으로 sklearn 전처리를 배우면 계속 나오는 핵심 패턴이다.

```python
preprocessor.fit(x_train)               # Train으로 규칙 학습
x_train_new = preprocessor.transform(x_train)   # Train 변환
x_test_new = preprocessor.transform(x_test)     # Test는 기존 규칙으로 변환만
```

또는 Train에서는 `fit_transform()`으로 한 번에 처리할 수 있다.

```python
x_train_new = preprocessor.fit_transform(x_train)
x_test_new = preprocessor.transform(x_test)
```

평균, 표준편차, Encoder, Scaler 등은 모두 **Train에서만 학습**하고, Test에는 그 규칙을 그대로 적용한다. 전처리까지 포함해서 Test 데이터는 모델 개발 과정에서 **처음 보는 데이터처럼 취급**해야 한다.

**핵심 정리**

머신러닝의 기본 구조는 `Feature X → Model → Prediction ŷ → Target y와 비교 → Metric`이다.

Model 사용의 기본 3단계는 다음과 같다.

```python
model = LogisticRegression()      # 1. 모델 생성
model.fit(x_train, y_train)       # 2. 모델 학습
y_pred = model.predict(x_test)    # 3. 새로운 데이터 예측
```

Data Preprocessing 흐름: `Cleaning → Feature Engineering → Feature/Target Split → Number/Category Split → Encoding → Scaling → Final Dataset`.

오늘 배운 것 중 가장 중요한 건 **Train은 fit 가능, Test는 fit 금지(transform만)** 이라는 원칙이다. 결측치 대체 기준이든 Encoder든 Scaler든, Train에서 학습한 규칙을 Test에 그대로 적용해야 Data Leakage를 막을 수 있다.

전체 흐름을 한 줄로 정리하면:

```text
데이터 수집 → EDA → Train/Test 분리 → Cleaning → Feature Engineering
→ Feature/Target 분리 → 수치형/범주형 분리 → Encoding → 최종 Feature 생성
→ Model 학습 → Prediction → Evaluation
```
