**0. 경진대회 메모**

경진대회를 진행할 때는 단순히 최종 점수만 기록하는 것이 아니라 **어떤 시도를 했고, 그 시도가 점수를 어떻게 변화시켰는지** 기록하는 것이 중요하다.

| 날짜 | 시도한 내용 | Train Score | Test Score |
|---|---|---:|---:|
| 09/04 | 기본 모델 | 0.82 | 0.78 |
| 09/04 | 결측치 처리 변경 | 0.84 | 0.81 |
| 09/05 | Feature 추가 | 0.88 | 0.83 |

이렇게 기록하면 어떤 시도가 성능을 높였는지, 어떤 시도가 오버피팅을 만들었는지, 다음에 어떤 실험을 해야 하는지 판단하기 쉬워진다.

Train Score와 Test Score를 같이 확인해야 하는 이유도 있다.

```text
Train Score 매우 높음, Test Score 낮음
→ 학습 데이터만 너무 잘 외운 상태 → Overfitting 가능성

Train Score 낮음, Test Score 낮음
→ 모델이 패턴 자체를 제대로 학습하지 못함 → Underfitting 가능성
```

경진대회에서는 **점수 + 실험 내용 + 날짜 + 사용한 코드**를 함께 관리하는 것이 좋다.

**1. 단순 선형 회귀(Simple Linear Regression)**

회귀(Regression)는 **연속적인 숫자 값을 예측하는 머신러닝 방법**이다. 집값, 시험점수, 매출, 온도, 판매량처럼 결과가 하나의 숫자로 나오는 문제에 사용할 수 있다.

"공부 시간 → 시험 점수 예측" 문제를 생각해보자. 공부 시간을 x, 시험 점수를 y라고 하면:

| 공부 시간 x | 시험 점수 y |
|---:|---:|
| 1 | 50 |
| 2 | 60 |
| 3 | 70 |
| 4 | 80 |
| 5 | 90 |

공부 시간이 늘어날수록 시험 점수도 증가한다. 이 데이터들을 하나의 직선으로 표현하는 것이 단순 선형 회귀다.

**단순 선형 회귀식**: `ŷ = wx + b`

| 기호 | 의미 |
|---|---|
| x | Feature, 입력값 |
| y | 실제 정답 |
| ŷ | 모델이 예측한 값 |
| w | Weight, 가중치 |
| b | Bias / Intercept, 절편 |

**y와 ŷ의 차이**: y는 실제 정답, ŷ는 모델이 예측한 답이다. 실제 시험점수가 72점인데 모델이 69점이라고 예측했다면 y=72, ŷ=69이고, 이 차이로 모델이 잘 예측했는지 판단한다.

**Feature란**: 모델에게 주는 입력 정보. "공부 시간 → 시험 점수" 문제라면 공부 시간이 Feature, 시험 점수가 Target이다.

**Target이란**: 모델이 맞혀야 하는 정답. 모델에게 x=4를 주면 "4시간 공부하면 몇 점일까?"를 계산하고, 이때 계산된 값이 ŷ이다.

**가중치 Weight**: x가 1만큼 변했을 때 y가 얼마나 변하는지 나타내는 값이다. `ŷ=10x+40`이라면 w=10이다.

```text
x=1 → ŷ=10×1+40=50
x=2 → ŷ=10×2+40=60
x=3 → ŷ=10×3+40=70
```

x가 1 증가할 때마다 y가 10씩 증가하므로 10이 가중치다. 수학의 직선 `y=ax+b`에서 a가 기울기인 것처럼, Weight w도 기울기와 같은 개념이다.

**Weight 부호에 따른 그래프 모양**:
- `w>0`: x 증가 → y 증가 (우상향)
- `w<0`: x 증가 → y 감소 (우하향)
- `w=0`: x가 변해도 y는 그대로

**절편 Bias**: x가 0일 때의 예측값. `ŷ=10x+40`이면 b=40이고, x=0을 넣으면 ŷ=40이 된다. Weight는 직선의 기울기, Bias는 직선의 위치라고 생각하면 된다 — w가 바뀌면 직선이 회전하고, b가 바뀌면 직선 전체가 위/아래로 이동한다.

**Python으로 직접 계산**:

```python
def linear_regression(x, w, b):
    y_hat = w * x + b
    return y_hat

x, w, b = 3, 10, 40
prediction = linear_regression(x, w, b)  # 70
```

NumPy를 쓰면 여러 데이터를 한 번에 계산할 수 있다.

```python
import numpy as np

x = np.array([1, 2, 3, 4, 5])
w, b = 10, 40
y_hat = w * x + b  # array([50, 60, 70, 80, 90])
```

**2. 손실함수(Loss Function)와 MSE**

모델이 예측했으면 실제값과 얼마나 다른지 확인해야 한다. 이 차이를 숫자로 나타낸 것이 **손실(Loss)**이다.

실제값 y=70, 예측값 ŷ=65라면 차이는 -5다. 하지만 오차 +5와 -5를 그냥 더하면 0이 되어버려서, 실제로는 두 번 틀렸는데 오차가 0처럼 보이는 문제가 생긴다. 그래서 오차를 **제곱**한다(`(ŷ-y)²`). 5²=25, (-5)²=25가 되어 음수/양수가 상쇄되는 문제가 사라진다.

여러 데이터의 오차 제곱을 계산한 뒤 평균을 내는 방법이 **MSE**다.

```python
import numpy as np

y = np.array([50, 60, 70])
y_hat = np.array([48, 65, 68])

error = y_hat - y            # [-2, 5, -2]
squared_error = error ** 2   # [4, 25, 4]
mse = squared_error.mean()   # 11.0
```

MSE가 크면 실제값과 예측값 차이가 커서 잘못 예측한 것이고, 작으면 잘 예측한 것이다. 모델의 목표는 MSE를 작게 만드는 것이다.

**손실함수와 2차함수**: 단순 선형회귀에서 MSE를 Weight w의 함수로 생각하면 U자 모양의 2차함수 형태가 나타날 수 있고, 가장 아래쪽이 Loss가 가장 작은 Weight다. 모델 학습은 결국 **Loss가 가장 작은 Weight와 Bias를 찾는 과정**이다. 다만 모든 손실함수가 무조건 2차함수는 아니고, 단순 선형회귀에서 MSE를 w,b에 대해 볼 때 그렇게 나타난다는 정도로 이해하면 된다.

**3. Gradient, 미분, Gradient Descent**

**Gradient**는 현재 위치에서 어느 방향으로 가면 값이 얼마나 변하는지 알려주는 기울기다. 산에서 가장 낮은 곳을 찾는 것에 비유하면, 산의 높이가 Loss, 현재 위치가 Weight/Bias다.

**미분**은 현재 위치의 기울기가 어느 방향인지 알려주는 계산이다. MSE를 Weight w에 대해 미분하면 `(2/N)Σ(wxᵢ+b-yᵢ)xᵢ`가 되고, `wxᵢ+b=ŷᵢ`이므로 `(2/N)Σ(ŷᵢ-yᵢ)xᵢ`로도 쓸 수 있다. 핵심은 "(예측값-실제값)으로 얼마나 틀렸는지 확인 × Feature x로 Weight의 영향 확인 → 모든 데이터의 평균"이다.

**Gradient Descent(경사하강법)**는 경사를 따라 아래로 내려가며 Loss가 가장 낮은 지점을 찾는 방법이다.

**Weight 업데이트**: `w_new = w_old - learning_rate × gradient`. Gradient는 값이 커지는 방향을 알려주므로, Loss를 작게 만들려면 반대 방향으로 가야 해서 뺀다.

- Gradient 양수(+5) → Weight 감소
- Gradient 음수(-5) → Weight 증가 (마이너스×마이너스=플러스)

**Learning Rate**는 한 번에 얼마나 크게 움직일지를 결정한다. 너무 크면 최소점을 계속 지나칠 수 있고, 너무 작으면 학습이 매우 느려진다.

**Bias의 Gradient**는 `(2/N)Σ(ŷᵢ-yᵢ)` 형태다. Weight는 `평균((예측-실제)×x)`, Bias는 `평균(예측-실제)`를 이용한다고 생각하면 쉽다.

---

**4. Gradient Descent 직접 구현**

```python
import numpy as np

x = np.array([1, 2, 3, 4, 5], dtype=float)
y = np.array([50, 60, 70, 80, 90], dtype=float)

w, b = 0.0, 0.0
learning_rate = 0.01
epochs = 5000

for epoch in range(epochs):
    y_hat = w * x + b                     # 1. 예측
    error = y_hat - y                      # 2. 차이
    mse = np.mean(error ** 2)              # 3. MSE

    w_gradient = 2 * np.mean(error * x)    # 4. Weight Gradient
    b_gradient = 2 * np.mean(error)        # 5. Bias Gradient

    w = w - learning_rate * w_gradient     # 6. Weight 업데이트
    b = b - learning_rate * b_gradient     # 7. Bias 업데이트

    if epoch % 500 == 0:
        print(epoch, mse, w, b)
```

이 과정은 `초기 w,b → 예측 → 실제 y와 비교 → Error → MSE → Gradient 계산 → w,b 수정 → 다시 예측 → 반복`으로 이어지며, 이게 머신러닝의 학습이다. 학습이 잘 되면 `w≈10`, `b≈40`에 가까운 값이 나오고, `new_x=6`을 넣으면 약 100 근처의 값이 예측된다.

Weight와 Bias처럼 모델이 학습으로 찾는 값은 **Model Parameter**, `learning_rate`/`epochs`처럼 사람이 정하는 값은 **Hyperparameter**라고 한다.

**손실은 반드시 0이 될까?**: 항상 그런 건 아니다. 데이터가 정확히 하나의 직선 위에 있고 모델이 완벽히 찾으면 MSE가 0이 될 수도 있지만, 실제 데이터에는 노이즈, 측정 오류, 숨겨진 변수 등이 있어 현실에서는 완벽하게 0이 되지 않는 경우가 많다.

**5. 다중 선형 회귀와 Regularization**

단순 선형 회귀는 Feature가 하나였지만, 실제로는 여러 원인이 결과에 영향을 준다. 집값은 평수, 방 개수, 층수, 지하철 거리 등의 영향을 받는다.

**다중 선형 회귀식**: `y = w₁x₁ + w₂x₂ + ... + wₙxₙ + b`. 예를 들어 `집값 = 100x₁ + 500x₂ - 20x₃ + 10000`이면, w₁=100(집 크기 커지면 집값 증가), w₃=-20(역에서 멀어질수록 집값 감소)처럼 해석할 수 있다. 데이터가 많아지면 행렬로 `ŷ=XW+b`처럼 표현한다.

**Regularization**은 Normalization(데이터 Scale 조정)과는 다른 개념으로, Weight가 너무 커지지 못하게 벌점을 주는 방법이다. 모델이 Train 데이터만 너무 잘 맞추면 Test 성능이 나빠지는 **Overfitting**이 생길 수 있는데, 이때 Weight가 커지면 벌점을 추가한다: `Loss = 기존 MSE + Weight에 대한 벌점`.

- **L1 Regularization**: `Loss = MSE + λΣ|wᵢ|`. λ는 규제 강도(Learning Rate와는 다른 개념 — Learning Rate는 한 번에 얼마나 수정할지, λ는 Weight가 커지는 걸 얼마나 강하게 막을지). L1은 일부 Weight를 정확히 0으로 만들 수 있어 **Feature Selection**이 가능하다.
- **L2 Regularization**: `Loss = MSE + λΣwᵢ²`. 완전히 0으로 만들기보다는 큰 Weight를 작은 Weight로 부드럽게 줄이는 경향이 있다.

| 종류 | 벌점 | 특징 |
|---|---|---|
| L1 | \|w\| | 일부 Weight를 0으로 만들 수 있음 |
| L2 | w² | Weight 전체를 부드럽게 줄임 |

**6. LinearRegression 실습**

```python
from sklearn.linear_model import LinearRegression

model = LinearRegression()
model.fit(x_train, y_train)
y_pred = model.predict(x_test)

model.coef_       # 학습된 Weight
model.intercept_  # 학습된 Bias
```

LinearRegression은 기본적으로 **최소제곱법(Ordinary Least Squares)**을 사용하며, 목표는 `Σ(yᵢ-ŷᵢ)²`를 최소로 만드는 Weight와 Bias를 찾는 것이다. Feature가 5개면 Weight도 보통 5개다.

**왜 제약이 있는 모델을 쓸까**: 제약 없는 LinearRegression은 Train에 너무 맞춰질 수 있다(Train 0.99, Test 0.70 → Overfitting 가능성). Ridge를 쓰면 Train은 0.92로 낮아져도 Test가 0.85로 더 좋아질 수 있다. 목표는 Train 점수를 최고로 만드는 게 아니라 처음 보는 데이터에서도 잘 예측하는 것이다.

**Hyperparameter Tuning**: Ridge의 `alpha`처럼 사람이 정하는 값(작으면 규제 약함, 크면 규제 강함)을 여러 개 시도하면서 평가 성능이 좋아지는 값을 찾는 과정이다.

**7. 혼동행렬(Confusion Matrix) 자세히 보기**

분류 모델을 만들고 나면 가장 먼저 궁금한 건 "모델이 어떤 데이터를 맞혔고 어떤 데이터를 틀렸는가?"다. Accuracy만 보면 전체 중 몇 개를 맞혔는지만 알 수 있지만, 실제로는 "0을 0으로 맞힌 것 / 1을 1로 맞힌 것 / 0인데 1이라고 잘못 예측한 것 / 1인데 0이라고 잘못 예측한 것"을 따로 보는 게 중요하다. 이 네 가지를 표로 정리한 것이 **혼동행렬**이다.

암 진단 모델을 예로 들면(0=정상, 1=암), 실제값과 예측값을 비교했을 때 4가지 경우가 나온다.

| | 예측 Negative(0) | 예측 Positive(1) |
|---|---:|---:|
| **실제 Negative(0)** | TN | FP |
| **실제 Positive(1)** | FN | TP |

sklearn `confusion_matrix()`의 결과도 기본적으로 `[[TN, FP], [FN, TP]]` 순서다.

**이름 외우는 법**: 첫 단어(True=맞음, False=틀림) + 두 번째 단어(Positive=1이라고 판단, Negative=0이라고 판단).

- **TP**: 실제 1, 예측 1 → 맞음. 실제 암환자를 모델도 암이라고 예측
- **TN**: 실제 0, 예측 0 → 맞음. 실제 정상을 모델도 정상이라고 예측
- **FP**: 실제 0, 예측 1 → 틀림. 정상 사람을 암환자라고 잘못 판단
- **FN**: 실제 1, 예측 0 → 틀림. 암환자를 정상이라고 잘못 판단 — 이 경우는 치료 시기를 놓칠 수 있어 매우 위험할 수 있다

```text
                예측
              0        1
          ┌────────┬────────┐
실제   0  │   TN   │   FP   │
          ├────────┼────────┤
       1  │   FN   │   TP   │
          └────────┴────────┘
```

**실제 숫자로 이해하기**: 혼동행렬이 `[[70, 10], [5, 15]]`로 나왔다면 TN=70, FP=10, FN=5, TP=15다.

| | 예측 정상(0) | 예측 암(1) |
|---|---:|---:|
| 실제 정상(0) | 70 | 10 |
| 실제 암(1) | 5 | 15 |

TN=70(실제 정상 70명을 정상으로 맞춤), FP=10(실제 정상 10명을 암이라고 잘못 예측), FN=5(실제 암환자 5명을 정상이라고 잘못 예측), TP=15(실제 암환자 15명을 암으로 맞춤).

**Python으로 만들기**:

```python
from sklearn.metrics import confusion_matrix

y_true = [0, 0, 0, 0, 1, 1, 1, 1]
y_pred = [0, 0, 1, 0, 1, 0, 1, 1]

cm = confusion_matrix(y_true, y_pred)
# [[3 1]
#  [1 3]]
# TN=3, FP=1, FN=1, TP=3
```

`cm.ravel()`을 쓰면 네 값을 한 번에 변수로 꺼낼 수도 있다.

```python
tn, fp, fn, tp = cm.ravel()
print('TN :', tn)  # 3
print('FP :', fp)  # 1
print('FN :', fn)  # 1
print('TP :', tp)  # 3
```

**Heatmap으로 보기**:

```python
import seaborn as sns
import matplotlib.pyplot as plt
from sklearn.metrics import confusion_matrix

cm = confusion_matrix(y_true, y_pred)

plt.figure(figsize=(6, 5))
sns.heatmap(
    cm, annot=True, fmt='d', cmap='Blues',
    xticklabels=['Pred 0', 'Pred 1'],
    yticklabels=['True 0', 'True 1']
)
plt.xlabel('Predicted')
plt.ylabel('Actual')
plt.title('Confusion Matrix')
plt.show()
```

읽는 법: 왼쪽 위=TN, 오른쪽 위=FP, 왼쪽 아래=FN, 오른쪽 아래=TP. 대각선(TN, TP)이 맞힌 데이터, 대각선 밖(FP, FN)이 틀린 데이터다.

**비율로 보기**: 데이터가 많으면 개수보다 비율이 편할 수 있다.

```python
cm_ratio = confusion_matrix(y_true, y_pred, normalize='true')
```

`normalize='true'`는 각 실제 Class 기준으로 몇 %를 어떻게 예측했는지 보여준다. 예를 들어 `[[0.90, 0.10], [0.25, 0.75]]`면 실제 0 중 90%는 0으로 맞고 10%는 1로 잘못 예측, 실제 1 중 25%는 0으로 잘못 예측되고 75%는 1로 맞았다는 뜻이다. sklearn에서는 `normalize=None`(실제 개수), `'true'`(실제값 기준 비율), `'pred'`(예측값 기준 비율), `'all'`(전체 데이터 기준 비율) 중 선택할 수 있다.

**Accuracy와 혼동행렬의 관계**: Accuracy는 네 숫자 중 맞힌 데이터만 본다. `Accuracy=(TP+TN)/(TP+TN+FP+FN)`. 위 예시로 계산하면 `(70+15)/100=0.85`, 즉 85%다.

**Accuracy만 보면 안 되는 이유**: 정상 99명, 암환자 1명인 데이터에서 모델이 전부 "정상"이라고 예측하면 99명 맞고 1명 틀려서 Accuracy=99%가 나온다. 겉보기엔 매우 좋은 모델 같지만 암환자를 단 한 명도 찾지 못했다. Accuracy가 높다고 무조건 좋은 모델은 아니며, 특히 Class 비율이 불균형한 데이터에서는 더욱 주의해야 한다.

**8. Precision과 Recall**

혼동행렬에서 중요한 오류는 FP와 FN인데, 상황에 따라 FP를 줄이는 게 중요한 경우와 FN을 줄이는 게 중요한 경우가 다르다. 그래서 Precision과 Recall을 함께 본다.

**Precision(정밀도)**: 모델이 Positive라고 예측한 것들 중 진짜 Positive가 얼마나 있는가. `Precision=TP/(TP+FP)`. 모델이 암환자라고 예측한 사람이 20명인데 실제 암환자가 15명이면 Precision=75%. "내가 암이라고 한 사람들 중 진짜 암환자는 몇 %인가?"

**Recall(재현율)**: 실제 Positive 중 모델이 얼마나 찾아냈는가. `Recall=TP/(TP+FN)`. 실제 암환자가 20명인데 모델이 15명을 찾아냈으면 Recall=75%. "실제 암환자들을 얼마나 많이 찾아냈는가?"

```text
Precision → 내가 잡은 사람 중 진짜 범인은 몇 명?
Recall    → 실제 범인 중 내가 몇 명을 잡았나?
```

**어떤 지표를 더 중요하게 볼까**: Precision과 Recall 중 뭘 더 신경 써야 하는지는 결국 "어느 쪽 실수의 비용이 더 큰가"로 판단하면 된다.

- **Precision이 중요한 경우**: FP(헛경보)의 비용이 큰 상황. 스팸 필터가 대표적인데, 정상 메일 하나를 스팸으로 잘못 분류해서 중요한 메일을 놓치는 게, 스팸 메일 몇 통이 받은편지함에 들어오는 것보다 훨씬 치명적이다. 그래서 "1이라고 판단한 것 중 진짜 1이 얼마나 되는지"를 엄격하게 봐야 한다.
- **Recall이 중요한 경우**: FN(놓침)의 비용이 큰 상황. 암 진단이 대표적인데, 실제 암환자를 정상이라고 놓치면 치료 시기를 놓쳐 생명이 위험해질 수 있다. 반면 정상인이 암 의심으로 재검사를 받는 불편함은 그에 비하면 훨씬 작은 비용이다. 그래서 "실제 1을 얼마나 놓치지 않고 찾아냈는지"가 더 중요하다.

이 기준을 여러 상황에 적용해보면:

즉 무조건 "Precision이 좋다" 혹은 "Recall이 좋다"가 정해져 있는 게 아니라, **놓쳤을 때(FN)와 잘못 잡았을 때(FP) 중 어느 쪽 대가가 더 큰지**를 먼저 따져보고 그에 맞게 Threshold를 조절하거나 어떤 지표를 우선할지 정해야 한다는 걸 새삼 느꼈다.


| 상황 | Positive의 의미 | FP(헛경보)의 비용 | FN(놓침)의 비용 | 더 중시할 지표 |
|---|---|---|---|---|
| 공항 보안 검색 | 위험 물품 소지 | 무고한 승객 추가 검사, 대기 시간 증가 | 위험 물품 반입 실패 | Recall |
| 고객 이탈 예측 | 이탈할 고객 | 안 떠날 고객에게 불필요한 쿠폰 제공 | 실제 이탈 고객을 놓쳐 매출 손실 | Recall 우선, Precision도 관리 |
| 온라인 쇼핑 사기 주문 탐지 | 사기 주문 | 정상 주문 차단, 고객 불만 | 사기 주문 승인, 환불·상품 손실 | Recall |
| 유해 콘텐츠 필터링 | 유해 콘텐츠 | 정상 게시물 삭제, 표현의 자유 논란 | 유해 게시물 노출 | 서비스 성격에 따라 다름 |
| 자율주행 보행자 감지 | 보행자 존재 | 불필요한 급정거, 승차감 저하 | 보행자를 놓쳐 사고·인명 피해 | Recall |
| 재고 부족 예측 | 품절 위험 상품 | 불필요한 추가 발주, 보관비 증가 | 실제 품절로 판매 기회 손실 | Recall 우선 |
| 장학금 부정 수급 탐지 | 부정 수급자 | 정상 학생이 억울하게 소명 절차를 거침 | 부정 수급을 놓쳐 예산 낭비 | Precision·Recall 함께 |

몇 가지는 왜 그런지 조금 더 뜯어보면:

- **자율주행 보행자 감지**: FP는 그냥 차가 한 번 더 조심스럽게 서는 정도라 승차감이 떨어지는 수준이지만, FN은 보행자를 못 보고 지나치는 것이라 인명 사고로 직결될 수 있다. 그래서 여기서는 Recall이 특히 중요하다.
- **유해 콘텐츠 필터링**은 서비스 성격에 따라 답이 달라지는 흥미로운 케이스였다. 어린이 대상 플랫폼이라면 유해물을 놓치는 FN이 훨씬 위험하지만, 자유로운 토론이 핵심인 플랫폼이라면 정상 게시물을 지우는 FP도 신뢰도에 큰 타격을 준다.
- **장학금 부정 수급 탐지**처럼 FP(억울한 학생)와 FN(예산 낭비) 모두 무시할 수 없는 문제도 있다. 이런 경우엔 한쪽만 극단적으로 밀어붙이기보다 Precision, Recall, F1을 같이 보면서 균형점을 찾아야 한다.

결국 "평가 지표는 공식만 보고 정하는 게 아니라, 실제 문제에서 어떤 실수가 더 아픈지를 먼저 따져보고 골라야 한다"는 게 오늘 배운 것 중 가장 실무적으로 와닿는 부분이었다.

**F1 Score와 조화평균**: Precision과 Recall 중 하나만 보기 애매한 경우도 있다. 예를 들어 Precision=0.95, Recall=0.30인 모델은 정밀하긴 하지만 실제 Positive 대부분을 놓치고 있다. 이럴 때 Precision과 Recall을 함께 고려하는 지표가 **F1 Score**다.

`F1 = 2×Precision×Recall / (Precision+Recall)`

F1은 단순 평균 `(Precision+Recall)/2`이 아니라 **조화평균(Harmonic Mean)**을 사용한다는 점이 중요하다. 조화평균은 한쪽 값이 지나치게 낮으면 전체 점수도 크게 낮아지는 특징이 있다. Precision=1.0, Recall=0.1인 모델을 단순 평균으로 계산하면 0.55로 꽤 괜찮아 보이지만, 실제로는 Positive의 90%를 놓치고 있는 나쁜 모델이다. 조화평균을 쓰는 F1은 이런 불균형을 훨씬 잘 반영해서 낮은 점수를 준다.

```python
from sklearn.metrics import accuracy_score, precision_score, recall_score, f1_score

print('Accuracy :', accuracy_score(y_true, y_pred))
print('Precision:', precision_score(y_true, y_pred))
print('Recall   :', recall_score(y_true, y_pred))
print('F1 Score :', f1_score(y_true, y_pred))
```

**비율 혼동행렬도 Heatmap으로**: 위에서 본 `normalize='true'` 결과도 Heatmap으로 그리면 한눈에 보기 좋다.

```python
cm_ratio = confusion_matrix(y_true, y_pred, normalize='true')

plt.figure(figsize=(6, 5))
sns.heatmap(
    cm_ratio, annot=True, fmt='.2f', cmap='Blues',
    xticklabels=['Predicted 0', 'Predicted 1'],
    yticklabels=['Actual 0', 'Actual 1']
)
plt.xlabel('Predicted')
plt.ylabel('Actual')
plt.title('Normalized Confusion Matrix')
plt.show()
```

**9. Threshold와 ROC Curve**

**Threshold란**: 많은 분류 모델은 바로 0/1을 만드는 게 아니라 먼저 **확률**을 계산한다. 예를 들어 A 고객 이탈확률 0.10, B 0.35, C 0.62, D 0.91처럼 나올 수 있다. 최종적으로는 0/1 중 하나를 선택해야 해서 기준선을 만드는데, 그 기준이 **Threshold**다.

일반적인 이진분류에서는 Threshold=0.5로 두고 `확률 >= 0.5 → 1`, `확률 < 0.5 → 0`으로 분류한다. Threshold를 0.3으로 낮추면 0.35였던 데이터도 1로 분류되어, 더 많은 데이터가 1로 판단된다(보통 TP 증가 가능, FP도 증가 가능). Threshold를 0.8로 높이면 정말 확실한 것만 1로 판단해서(보통 FP 감소 가능, 하지만 FN 증가 가능, Recall 하락 가능). 즉 Threshold 하나만 바꿔도 TP/TN/FP/FN이 전부 달라질 수 있다.

**ROC Curve**: Receiver Operating Characteristic의 약자로, Threshold를 여러 값으로 바꾸면서 FPR과 TPR이 어떻게 변하는지 그린 그래프다.

- **x축 FPR** (False Positive Rate): `FPR=FP/(FP+TN)`. 실제 Negative 중 Positive라고 잘못 예측한 비율. 정상인 100명 중 20명을 암이라고 잘못 예측했으면 FPR=20%.
- **y축 TPR** (True Positive Rate): `TPR=TP/(TP+FN)`. 이 값은 Recall과 같다. 실제 Positive 중 모델이 얼마나 잘 찾아냈는지를 의미한다.

우리가 원하는 모델은 FPR은 낮고 TPR은 높은 모델, 즉 그래프에서 **왼쪽 위**에 가까울수록 좋은 모델이다.

```text
TPR
1.0 | ●────────────
    |  \
    |   \
0.8 |    ●
    |     \
0.6 |      ●
0.0 |____________________
     0.0              1.0
             FPR
```

Threshold를 0.9, 0.8, 0.7...로 하나씩 바꾸면 각각에서 TPR/FPR이 달라지고, 그 점들을 전부 연결한 게 ROC Curve다. 그래프에는 보통 대각선이 그려지는데, 이 선은 **랜덤으로 찍는 모델**의 기준이다. ROC Curve가 대각선 근처면 랜덤에 가깝고, 왼쪽 위로 올라갈수록 좋은 모델이다.

**predict()와 predict_proba()**: `predict()`는 최종 Class(0 또는 1)를 반환하지만, `predict_proba()`는 각 Class가 될 확률을 반환한다.

```python
y_pred = model.predict(x_test)          # [0, 0, 1, 0, 1, ...]

y_prob = model.predict_proba(x_test)
# [[0.90, 0.10], [0.70, 0.30], [0.20, 0.80]]
```

첫 번째 데이터는 0일 확률 90%, 1일 확률 10%라는 뜻이다. ROC Curve를 만들 때는 보통 Class 1의 확률을 사용한다.

```python
y_score = model.predict_proba(x_test)[:, 1]  # 모든 Row의 1번 Column(Positive 확률)
```

**Python으로 ROC Curve 그리기**:

```python
from sklearn.metrics import roc_curve, roc_auc_score
import matplotlib.pyplot as plt

y_score = model.predict_proba(x_test)[:, 1]

fpr, tpr, thresholds = roc_curve(y_test, y_score)
auc_score = roc_auc_score(y_test, y_score)

plt.figure(figsize=(7, 6))
plt.plot(fpr, tpr, label=f'ROC-AUC = {auc_score:.3f}')
plt.plot([0, 1], [0, 1], linestyle='--')  # 랜덤 기준선
plt.xlabel('False Positive Rate')
plt.ylabel('True Positive Rate')
plt.title('ROC Curve')
plt.legend()
plt.show()
```

`roc_curve()`는 fpr(FPR 배열), tpr(TPR 배열), thresholds(각 지점에서 쓰인 Threshold) 세 가지를 반환한다.

**Threshold를 직접 바꿔보기**:

```python
threshold = 0.5
y_pred_05 = (y_score >= threshold).astype(int)

threshold = 0.3
y_pred_03 = (y_score >= threshold).astype(int)
```

Threshold를 낮추면 더 많은 데이터가 1로 분류되어 보통 Recall이 증가할 가능성이 있지만 FP도 증가하고 Precision은 감소할 수 있다. 반대로 Threshold를 높이면 FP는 줄지만 FN이 늘고 Recall이 떨어질 수 있다. 즉 Threshold는 Precision과 Recall의 균형을 조절하는 역할을 한다.

**10. AUC**

AUC는 Area Under the Curve, 즉 ROC Curve 아래쪽 면적이다. ROC Curve 자체는 그래프라서 모델 두 개를 숫자 하나로 비교하기 불편한데, 이 면적을 계산하면 하나의 숫자로 비교할 수 있다.

```python
from sklearn.metrics import roc_auc_score

auc_score = roc_auc_score(y_test, y_score)  # 예: 0.87
```

AUC는 보통 0~1 사이 값을 가진다.

```text
AUC = 0.5 → 랜덤(동전 던지기) 수준
AUC = 0.7 → 어느 정도 분류 가능
AUC = 0.8 → 꽤 좋은 분류
AUC = 0.9 → 매우 좋은 분류
AUC = 1.0 → 완벽한 분류
```

**조금 더 정확한 해석**: AUC는 "임의의 Positive 데이터 하나와 Negative 데이터 하나를 뽑았을 때, 모델이 Positive 데이터에 더 높은 점수를 줄 확률"로도 이해할 수 있다. 실제 Positive에 0.9, 실제 Negative에 0.2를 준다면 순서를 잘 구분한 것이고, 반대로 Positive에 0.3, Negative에 0.8을 준다면 잘못 구분한 것이다. AUC가 높다는 건 이런 **순위 구분 능력**이 좋다는 뜻이기도 하다.

**Accuracy와 ROC-AUC의 차이**: Accuracy는 보통 하나의 Threshold(예: 0.5)에서 계산한 성능이고, ROC-AUC는 Threshold를 여러 값으로 바꿔가며 본 전체적인 분류 능력이다.

**주의할 점**: ROC-AUC가 높다고 모든 상황에서 무조건 좋은 모델이라는 뜻은 아니다. Positive 1%, Negative 99%처럼 매우 심한 불균형 데이터에서는 ROC-AUC만 보는 게 충분하지 않을 수 있어, Precision/Recall/F1/PR-AUC 등도 같이 확인하는 게 좋다. 평가지표 하나만 보고 모델을 결정하지 않는 게 중요하다.

**혼동행렬과 ROC-AUC의 차이**: 혼동행렬은 현재 하나의 Threshold에서 무엇을 맞혔고 틀렸는지 보여주고, ROC-AUC는 Threshold를 여러 값으로 바꾸면서 Positive와 Negative를 전체적으로 얼마나 잘 구분하는지 본다.

| 지표 | 무엇을 보는가? |
|---|---|
| Confusion Matrix | 어떤 종류의 예측을 맞고 틀렸는가 |
| Accuracy | 전체에서 얼마나 맞혔는가 |
| Precision | Positive라고 한 것 중 진짜 Positive 비율 |
| Recall | 실제 Positive 중 찾아낸 비율 |
| F1 Score | Precision과 Recall의 균형 |
| ROC Curve | Threshold 변화에 따른 TPR/FPR 관계 |
| ROC-AUC | ROC Curve 전체를 하나의 숫자로 표현 |

**전체 흐름**:

```text
모델 → Positive일 확률 예측 → Threshold 선택 → 0/1로 변환 → 실제값과 비교
→ Confusion Matrix → Accuracy/Precision/Recall/F1
```

```text
예측 확률 → Threshold를 계속 변경 → 각 Threshold마다 TPR/FPR 계산
→ 점들을 연결 → ROC Curve → 곡선 아래 면적 → AUC
```

**11. 실제값과 예측값을 DataFrame으로 분석**

모델이 어디서 틀렸는지 보고 싶다면 실제값과 예측값을 하나의 DataFrame으로 만들 수 있다.

```python
import pandas as pd

df_train = pd.DataFrame({
    'y_true': y_train,
    'pred_tree': pred_train
})
df_train = pd.concat([df_train, pd.DataFrame(x_train)], axis=1)
```

실제 Positive인데 모델이 Negative라고 예측한 데이터(FN)를 찾아보면:

```python
c1 = (df_train['y_true'] == 1)
c2 = (df_train['pred_tree'] < 0.5)
c = c1 & c2

df_train.loc[c].head()
```

머신러닝에서는 "Accuracy=85%"만 보는 게 아니라 나머지 15%가 왜 틀렸는지 분석하는 것도 중요하다. FN 데이터에서 특정 나이, 특정 지역, 특정 Feature 값이 반복해서 나타난다면 새로운 Feature가 필요하다거나, 전처리 개선이 필요하다거나, 데이터 추가가 필요하다거나, 모델을 바꿔야 한다는 힌트를 얻을 수 있다.

---

**핵심 정리**

**회귀 흐름**: `ŷ=wx+b → Weight/Bias → Prediction → 실제 y와 비교 → Error → MSE → Gradient → Gradient Descent → Weight/Bias 업데이트 → 모델 학습`. Feature가 많아지면 다중 선형 회귀가 되고, Weight가 많아지며 Overfitting 가능성이 생겨 Regularization(L1/L2)을 사용한다.

**분류 흐름**: 실제값+예측값 → Confusion Matrix → Accuracy/Precision/Recall/F1/ROC-AUC.

```text
혼동행렬  → 어디서 틀렸냐?
Accuracy → 전체적으로 몇 개 맞혔냐?
Precision → 1이라고 한 것 중 진짜 1이 몇 개냐?
Recall   → 실제 1 중 몇 개를 찾아냈냐?
ROC      → 기준선을 바꿔가면서 성능이 어떻게 변하냐?
AUC      → 그 ROC 성능을 숫자 하나로 표현하면 얼마냐?
```

머신러닝 모델의 학습은 결국 "예측 → 틀린 정도 계산 → 파라미터 수정 → 다시 예측 → 반복"이라고 이해하면 된다.
