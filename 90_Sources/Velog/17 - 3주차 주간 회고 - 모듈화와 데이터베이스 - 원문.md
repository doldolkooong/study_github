**📢 08.18 (화) - 게임 모듈화 & 데이터베이스 기초**

기존에 만들어뒀던 묵찌빠, 가위바위보, 하나빼기 게임을 각각 독립된 모듈(함수/파일)로 분리하는 리팩토링부터 시작해서, 오후에는 곧바로 데이터베이스 기초로 넘어간 날이었다.

> - 묵찌빠 / 가위바위보 / 하나빼기 모듈화 (재사용성·가독성 개선)
- 리눅스 파일 시스템 기초 (`.`, `..`, 숨김 파일)
- 데이터 유형 (정형/반정형 데이터)
- Docker로 DB 컨테이너 실행 & DBeaver 설치
- DBMS 종류 (RDBMS / NoSQL), SQL 구성 (DDL/DML/DCL)
- ERD 개념 & 데이터 모델링 순서 (요구사항 정의서 → 개념적 데이터 모델링)

게임 로직을 하나의 파일에 다 몰아 넣었던 코드를 모듈 단위로 쪼개보면서 "왜 모듈화를 하는지"를 몸으로 느꼈다. 11시부터 3시까지 실업급여 교육으로 인해 수업 외출을 하게 되었는데 DB 설치가 끝난 상태에서 수업에 들어와 3시 수업은 못 따라갔지만 이후에는 강사님께서 설치를 도와주셔서 따라갈 수 있었다.

**💻 08.19 (수) - MySQL 재설치 & 테이블 생성**

전날 설정했던 DB 컨테이너를 지우고 VSCode + Docker 환경에서 MySQL을 다시 설치하는 것부터 시작해, DBeaver 연결부터 테이블 생성·데이터 삽입까지 실습했다.

> - VSCode + Docker로 MySQL 재설치 (`docker-compose down` → `up -d`)
- DBeaver 연결 설정 (`allowPublicKeyRetrieval` 옵션)
- 데이터베이스/테이블 생성 (`create table`, `varchar`, `comment`)
- 데이터 삽입 (`insert into`), `auto_increment` & `primary key`

컨테이너를 내렸다가 다시 올리는 과정에서 DBeaver 연결이 한 번에 되지 않아 `allowPublicKeyRetrieval` 옵션을 직접 찾아 설정해봐야 했던 게 기억에 남는다. 처음엔 `id`를 매번 직접 넣어서 데이터를 추가하다가, `primary key`와 `auto_increment`를 적용하면 `id`가 자동으로 채번되고 `not null`+`unique` 제약도 같이 걸린다는 걸 알게 되면서 왜 실무에서 이 조합을 기본으로 쓰는지 이해가 됐다.

**💻 08.20 (목) - SQL 조회·정렬·그룹핑·조인**

DCL 개념과 MySQL 계정 권한(`Host` 컬럼의 `%`)을 살펴본 뒤, `SELECT/WHERE`부터 `ORDER BY`, `GROUP BY`, 서브쿼리를 활용한 `JOIN`까지 실제 쿼리를 직접 짜보며 데이터 조회 실습을 진행했다.

> - DCL 및 계정 권한 (`%` = 모든 IP 허용)
- Docker로 MySQL 접속 (`mysql -u root -p`)
- 데이터 조회 (`SELECT`, `WHERE`, `1=1` 관용 표현)
- 정렬 (`ORDER BY asc/desc`)
- SQL 실행 순서 (`from → where → order by → group by → select → limit`)
- 그룹핑 (`GROUP BY`, `count`, 별칭 `as`)
- 서브쿼리와 조인 (`JOIN`)으로 상위 고객/주문 금액 조회

작성 순서와 실제 DB의 실행 순서가 다르다는 걸 배운 게 가장 인상 깊었다. `from`으로 대상을 정하고 `where`로 걸러낸 뒤 마지막에 `select`로 원하는 컬럼만 뽑는다는 흐름을 알고 나니 쿼리가 왜 이런 구조로 짜여야 하는지 이해가 됐다. 서브쿼리를 여러 겹으로 쌓아 "주문별 총액 → 고객별 총액 → 상위 3명 → 고객 정보 조인" 순서로 문제를 풀어나갈 때는 처음엔 헷갈렸지만, 단계를 하나씩 쌓아 올린다고 생각하니 훨씬 수월했다.

**👍좋았던 점**

>- 게임 로직을 모듈로 분리해보고, DB 컨테이너를 직접 내렸다 다시 띄우면서 문제를 해결해보니 "일단 되게만 만드는" 코드에서 벗어나는 연습이 됐다.
- SQL 실행 순서(`from→where→order by→group by→select`)를 배우고 나서 그동안 막막했던 서브쿼리·조인 문제들이 하나씩 풀리기 시작해서 성취감이 컸다.
- 강사님께 코드 주석 작성법에 대한 구체적인 피드백을 받으면서, 그냥 코드를 따라 치는 게 아니라 왜 이렇게 짜는지 고민하는 습관을 들일 수 있었다.

<br>

**😂아쉬웠던 점**

>- 하루 만에 리눅스 파일 시스템, Docker, SQL 구성 요소까지 새로운 개념이 한꺼번에 쏟아지다 보니 소화하기 벅찬 날들이 있었다.
- DBeaver 연결 옵션(`allowPublicKeyRetrieval`)처럼 사소해 보이지만 놓치면 아예 진행이 안 되는 설정들이 있어서, 에러 메시지를 꼼꼼히 읽는 습관이 아직 부족하다는 걸 느꼈다.
- 게임 로직을 구현할 때마다 사용자 입력값에 대한 예외 처리를 놓치는 경우가 반복돼서, 코드를 짤 때부터 예외 상황을 먼저 고려하는 습관이 아직 부족하다는 걸 느꼈다.
