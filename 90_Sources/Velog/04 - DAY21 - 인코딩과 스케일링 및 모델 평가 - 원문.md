**1. 어제 만든 Encoding 결과 확인**

어제 만든 `add_one_hot_encoding()` 함수가 하는 일은 간단하다. 문자 데이터를 머신러닝이 이해할 수 있는 숫자로 바꿔주는 것.

```text
who              who_man  who_woman  who_child
man       →         1         0          0
woman     →         0         1          0
child     →         0         0          1
```

```python
from common.preprocessing import add_one_hot_encoding

x_train_enc, x_test_enc = add_one_hot_encoding(
    encoder, x_train_str, x_test_str
)

x_train_enc.shape, x_test_enc.shape
```
> ((712, 19), (179, 19))

`shape`는 (Row 개수, Column 개수)다. 여기서 중요한 점: 이 19개는 **전체 Feature 개수가 아니다.** 지금은 범주형 데이터만 Encoding한 상태고, `age`, `fare`, `sibsp`, `parch`, `pclass` 같은 원래 숫자 데이터는 따로 있다. 그래서 마지막에는 숫자 데이터 + Encoding된 문자 데이터를 다시 합쳐야 최종 Feature가 완성된다.

**2. Encoding 코드를 Enum으로 구조화**

어제는 One-Hot Encoding만 썼지만, 실제로는 Label Encoding, Ordinal Encoding, Target Encoding, Mean Encoding 등 여러 방법이 있다. 그때마다 `add_one_hot_encoding()`, `add_label_encoding()`처럼 함수를 계속 새로 만드는 건 비효율적이라, "Encoding 종류를 하나 정하고 → 같은 함수에 넣어서 사용"하는 구조로 바꿨다.

**Enum이 뭐냐면**: 사용할 수 있는 선택지를 미리 정해 놓는 것이다. 카페 음료 사이즈가 Small/Medium/Large밖에 없는 것처럼, Encoding도 OneHot/Label/Ordinal/Target 같은 선택지를 미리 만들어 놓는 개념이다.

```python
# common/encoding_constants.py
import enum
import category_encoders as ce

class EncodingType(enum.Enum):
    pass  # 아직 아무것도 등록 안 한 상태
```

처음에는 이렇게 시작해서 `assert encoding_type in EncodingType.__members__`로 올바른 값인지 검사하는 코드를 짰다. `assert`는 조건이 맞는지 검사하는 코드로, 조건이 False면 `AssertionError`가 발생한다.

이후 OneHot을 실제로 등록했다.

```python
class EncodingType(enum.Enum):
    OneHot = (
        enum.auto(),
        ce.OneHotEncoder(use_cat_names=True)
    )
```

`enum.auto()`는 Enum 번호를 Python이 알아서 정해주는 기능이라 직접 1, 2, 3을 붙이지 않아도 된다. `use_cat_names=True`는 Encoding된 컬럼 이름에 실제 범주 이름을 써서(`who_man`, `who_woman`처럼) 결과를 알아보기 쉽게 만들어준다.

`EncodingType.OneHot`의 `value`는 튜플이라 `value[0]`은 enum 번호, `value[1]`은 실제 Encoder(OneHotEncoder)다. 처음에는 함수에서 `encoding_type.value[1].fit(...)`처럼 직접 꺼내 썼는데, 이렇게 하면 코드를 볼 때마다 "1번에 뭐가 들어있었지?" 하고 헷갈리게 된다.

그래서 `fit()`, `transform()` 자체를 `EncodingType` 클래스 안으로 옮겼다.

```python
class EncodingType(enum.Enum):
    OneHot = (enum.auto(), ce.OneHotEncoder(use_cat_names=True))

    def fit(self, x_train_str, col):
        # self.value[1] → OneHotEncoder 객체
        self.value[1].fit(x_train_str[col].astype('category'))

    def transform(self, x_df, col):
        # fit()에서 배운 규칙으로 실제 데이터를 숫자로 변환
        return self.value[1].transform(x_df[col].astype('category'))
```

이제 `encoding_type.value[1].fit(...)` 대신 `encoding_type.fit(...)`처럼 훨씬 읽기 쉬운 코드가 됐다.

```python
def transform_encoding(encoding_type, x_train_str, x_test_str):
    assert encoding_type in EncodingType, "encoding_type 값이 올바르지 않습니다."

    x_train_enc = pd.DataFrame()
    x_test_enc = pd.DataFrame()

    for col in x_train_str.columns:
        encoding_type.fit(x_train_str, col)                      # 1. 학습
        encoded_col = encoding_type.transform(x_train_str, col)  # 2. Train 변환
        encoded_col_test = encoding_type.transform(x_test_str, col)  # 3. Test 변환 (fit 안 함)

        x_train_enc = pd.concat([x_train_enc, encoded_col], axis=1)   # 4. 결과 합치기
        x_test_enc = pd.concat([x_test_enc, encoded_col_test], axis=1)

    return x_train_enc, x_test_enc
```

```python
from common.preprocessing import transform_encoding
from common.encoding_constants import EncodingType

x_train_enc, x_test_enc = transform_encoding(
    EncodingType.OneHot, x_train_str, x_test_str
)
x_train_enc.shape, x_test_enc.shape  # ((712, 19), (179, 19))
```

코드는 더 정리됐지만 결과는 그대로였다.

**fit과 transform, 다시 한번 정리**: `fit()`은 "공부하기"다. Train의 `who` 컬럼에 man/woman/child 3종류가 있다는 걸 Encoder가 배우는 과정. `transform()`은 배운 규칙대로 실제로 숫자를 바꾸는 것(man→[1,0,0]). Train은 fit()+transform()을 하고, Test는 transform()만 한다. Test는 "시험지"라서 fit(=공부)을 하면 안 된다. Train은 문제집, Test는 시험지라고 생각하면 이해가 쉽다.

**3. Scaling**

문자 데이터는 숫자로 바꿨으니, 이제 원래 숫자 데이터(`pclass`, `age`, `sibsp`, `parch`, `fare`) 차례다. 그런데 `age`는 20~50 정도인데 `fare`는 7.5~500까지 값의 크기가 크게 다를 수 있다. 모델 입장에서는 숫자 크기가 다르면 특정 Feature를 더 크게 볼 수 있어서, 숫자의 크기를 비슷하게 맞추는 게 **Scaling**이다.

**Normalizer**: 일반적인 Scaling이 Column 기준으로 동작하는 데 비해, Normalizer는 Row 기준으로 동작한다. 한 사람의 값이 `[3, 4]`라면 이 Vector의 길이는 `√(3²+4²)=5`인데, Normalizer는 이 길이를 1로 만든다(`[0.6, 0.8]`, 길이 재계산하면 1). 방향은 그대로 두고 길이만 1로 맞추는 것이다. 일반적인 표 형태 데이터에서는 StandardScaler, RobustScaler, MinMaxScaler를 더 많이 쓰고, Normalizer는 문서 Vector, TF-IDF, Cosine Similarity처럼 방향이 중요한 문제에서 많이 쓴다.

```python
from sklearn.preprocessing import Normalizer

scaler = Normalizer()
x_scaled = scaler.fit_transform(x_train)   # Train: 학습 + 변환
x_test_scaled = scaler.transform(x_test)   # Test: 변환만
```

Test에서 fit하면 안 되는 이유는 Encoding과 마찬가지다. Train은 문제집, Test는 시험지라서, Test에 `scaler.fit()`을 하면 시험지를 미리 보고 공부한 셈이 된다. 이게 바로 **Data Leakage**다.

**PowerTransformer**: 한쪽으로 너무 쏠린 데이터의 모양을 좀 더 정돈해주는 도구. 오른쪽 꼬리가 긴 데이터를 조금 더 균형 있는 모양으로 바꿔준다.

**QuantileTransformer**: 데이터를 순위대로 줄 세워서 비슷한 간격으로 다시 배치하는 느낌이다. 10점/20점/30점/100점/1000점처럼 값 차이가 커도 1등~5등처럼 순위 기준으로 재배치할 수 있다. 여러 분위수를 이용해 변환한다.

**일반 Scaler 4종**:

- **StandardScaler**: 평균 0, 표준편차 1이 되도록 변환. 평균 나이가 30, 표준편차가 10이면 40세는 (40-30)/10=1, 20세는 (20-30)/10=-1이 된다. 평균보다 높으면 양수, 평균과 같으면 0, 낮으면 음수.
- **RobustScaler**: 평균/표준편차 대신 중앙값/사분위수를 사용해서 이상치가 있을 때 상대적으로 덜 영향을 받는다.
- **MinMaxScaler**: 주로 0~1 사이로 변환(10→0, 20→0.5, 30→1 같은 느낌). 단, 10000 같은 큰 이상치가 있으면 나머지 값들이 전부 0 근처로 몰릴 수 있다.
- **MaxAbsScaler**: 가장 큰 절댓값을 기준으로 나눈다. -10, 0, 5가 있으면 가장 큰 절댓값 10 기준으로 -10→-1, 0→0, 5→0.5가 된다.

| 방법 | 쉽게 말하면 |
|---|---|
| StandardScaler | 평균을 0 근처로 맞춤 |
| RobustScaler | 이상치 영향을 줄여서 맞춤 |
| MinMaxScaler | 주로 0~1로 맞춤 |
| MaxAbsScaler | 가장 큰 절댓값을 1로 맞춤 |
| Normalizer | 한 Row의 Vector 길이를 1로 맞춤 |

**Transformer → Scaler 순서**: 가격 데이터처럼 오른쪽으로 심하게 치우친 데이터는 `log1p() → StandardScaler` 순서가 이해하기 쉽다. log1p는 데이터 모양을 조절하고, StandardScaler는 데이터 크기를 조절하는 역할이기 때문이다. 참고로 로그는 "왼쪽으로 쏠렸을 때만" 쓰는 게 아니라, 일반적으로 **오른쪽 꼬리가 긴 데이터에서 큰 값을 압축**하기 위해 많이 사용한다.

**4. Titanic 숫자 데이터 Scaling 실습**

```python
x_train_number.shape, x_test_number.shape  # ((712, 5), (179, 5))
```

`pclass`, `age`, `sibsp`, `parch`, `fare` 총 5개 Feature다.

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()  # 아직 아무 데이터도 학습 안 한, "빈 계산기" 상태

x_train_scaled = scaler.fit_transform(x_train_number)  # 학습 + 변환
x_test_scaled = scaler.transform(x_test_number)          # 변환만
```

**왜 Encoding 때는 Column이 늘어나고 Scaling은 그대로일까?** Encoding은 `who`를 `who_man`, `who_woman`, `who_child`처럼 새로운 Column 자체를 만들지만, Scaling은 `age=45`를 `age=1.23`으로 값만 바꾸는 것이라 `age`라는 Feature 자체는 그대로다. 그래서 Scaling 전후로 Column 개수는 변하지 않는다.

```python
x_train_scaled.shape, x_test_scaled.shape  # ((712, 5), (179, 5))
```

실제 값을 보면:

```python
x_train_scaled[:5]
```
> array([[-1.61413602, 1.2322632, -0.47072241, -0.47934164, -0.07868358], ...])

원래 `age=45.5`, `fare=28.5` 같은 값이 `1.23`, `-0.07` 같은 값으로 바뀌었다. 값의 의미가 사라진 게 아니라 **평균을 기준으로 얼마나 위/아래에 있는지**를 나타내는 숫자로 바뀐 것이다.

StandardScaler 결과는 NumPy Array라 컬럼 이름이 없다. 다시 DataFrame으로 만들려면:

```python
x_train_number.columns
# Index(['pclass', 'age', 'sibsp', 'parch', 'fare'], dtype='str')

pd.DataFrame(data=x_train_scaled, columns=x_train_number.columns)
```

**5. Scaling도 파일로 함수화**

Encoding처럼 Scaling도 Enum 구조로 만들었다.

```python
# common/scaling_constants.py
import enum
import pandas as pd
from sklearn.preprocessing import StandardScaler

class ScalingType(enum.Enum):
    Standard = (enum.auto(), StandardScaler())  # 클래스가 아니라 객체로!

    def fit(self, x_train_number):
        self.value[1].fit(x_train_number)

    def transform(self, x_df):
        return self.value[1].transform(x_df)
```

여기서 짚어야 할 부분: `StandardScaler`(클래스 자체)와 `StandardScaler()`(실제로 만들어진 객체)는 다르다. 붕어빵 틀과 실제 붕어빵의 차이라고 생각하면 된다. `fit()`을 실제로 쓰려면 객체가 필요하므로 `StandardScaler()`로 만들어야 한다.

```python
def transform_scaling(scaling_type, x_train_number, x_test_number):
    assert scaling_type in ScalingType, "scaling_Type 값이 올바르지 않습니다."

    scaling_type.fit(x_train_number)  # 1. Train으로 학습

    x_train_scaled = pd.DataFrame(
        data=scaling_type.transform(x_train_number),
        columns=x_train_number.columns
    )  # 2. Train 변환

    x_test_scaled = pd.DataFrame(
        data=scaling_type.transform(x_test_number),  # Test는 fit 안 함
        columns=x_train_number.columns
    )  # 3. Test 변환

    return x_train_scaled, x_test_scaled
```

```python
from common.scaling_constants import ScalingType
from common.preprocessing import transform_scaling

x_train_scaled, x_test_scaled = transform_scaling(
    ScalingType.Standard, x_train_number, x_test_number
)
x_train_scaled.shape, x_test_scaled.shape  # ((712, 5), (179, 5))
```

**여기서 매우 중요한 Index 문제**가 생긴다. 원래 Train 데이터의 Index는 331, 733, 382...처럼 원본 Titanic Index를 유지하고 있는데, NumPy Array를 다시 DataFrame으로 만들면 Index가 0, 1, 2...로 새로 생성된다. 그러면 Scaling 데이터는 Index가 0, 1, 2...인데 Encoding 데이터는 331, 733, 382...인 상태가 된다.

`pd.concat(axis=1)`은 단순히 첫 번째 Row끼리, 두 번째 Row끼리 붙이는 게 아니라 **같은 Index끼리 붙인다.** 그래서 Index가 다르면 NaN이 생기거나 Row 수가 이상하게 늘어날 수 있다.

해결 방법으로 `reset_index(drop=True)`를 사용했다.

```python
return (
    x_train_scaled.reset_index(drop=True),
    x_test_scaled.reset_index(drop=True)
)
```

기존 Index(331, 733...)를 버리고 0, 1, 2...로 다시 만드는 것이다. 단, Encoding 데이터도 같은 방식으로 Index를 맞춰줘야 나중에 concat할 때 문제가 없다.

**6. 모델링 데이터 만들기**

Scaling된 숫자 Feature와 Encoding된 문자 Feature를 합친다.

```python
x_train_features = pd.concat([x_train_scaled, x_train_enc], axis=1)
y_train_target = y_train

x_test_features = pd.concat([x_test_scaled, x_test_enc], axis=1)
y_test_target = y_test
```

모델에게 데이터를 넣기 전에 제대로 만들어졌는지 검증했다.

```python
assert x_train_features.shape[0] == y_train_target.shape[0], "학습 데이터 수 오류 발생"
# Feature가 712개인데 정답이 700개면 서로 연결할 수 없기 때문

assert x_train_features.shape[1] == x_test_features.shape[1], "컬럼 수 오류 발생"
# Train에서 24개 Feature로 공부한 모델에게 Test에서 23개를 주면 안 되기 때문

assert x_test_features.shape[0] == y_test_target.shape[0], "평가 데이터 수 오류 발생"
```

**8. 지도학습 전체 절차**

실제 회사에서 머신러닝 프로젝트를 한다고 생각하면 다음 순서를 따르게 된다.

1. **회사 데이터 수집**: 담당자로부터 데이터를 받는다(고객정보.csv, 구매내역.csv 등).
2. **데이터의 메타 정보도 받기**: `status = 0`이 정상인지 탈퇴인지 미구매인지 모르면 분석할 수 없다. 컬럼 이름/의미, 숫자 코드 의미, 단위, 수집 기간, 결측치 의미 같은 정보도 함께 받아야 한다.
3. **Target 정의**: "그래서 뭘 예측할 건데?"가 가장 중요한 질문이다. 예를 들어 나이/성별/구매금액/구매횟수/탈퇴여부 데이터가 있고 "고객이 탈퇴할지" 예측하려 한다면, Target은 탈퇴 여부고 나머지가 Feature가 된다. Target을 먼저 정해야 Feature도 정할 수 있다.
4. **Target 분석**: 범주(2개=이진분류, 3개 이상=다중분류)인지 연속 숫자(회귀)인지 판단한다. 분류라면 Class 비율도 확인해야 한다. 정상 98%, 이상 2%처럼 극단적이면 모델이 "이상" 데이터를 거의 못 보고 학습하는 문제가 생긴다.
5. **EDA**: Target과 Feature의 관계를 확인한다("나이가 많을수록 구매 확률이 높은가?" 같은 질문). Feature끼리 상관관계가 있다고 무조건 삭제하는 건 아니고, 모델 종류와 데이터 의미를 같이 봐야 한다.
6. **데이터 전처리**:
   - **결측치**: "20% 이상이면 삭제"는 절대 법칙이 아니다. 중요한 의료 검사 데이터라면 결측치가 많아도 사용할 수 있다. 결측치를 채울 때 전체 평균 대신 남성/여성 평균처럼 비슷한 그룹끼리 나눠서 채울 수도 있는데, **Target을 이용해서 채우면 안 된다** — 정답을 미리 보고 Feature를 만드는 셈이라 Data Leakage가 된다.
   - **Feature 생성**: `sibsp + parch → family_cnt`처럼 새 Feature를 만든다.
   - **중복 제거**: `pclass↔class`처럼 같은 정보인 Feature, `survived↔alive`처럼 Target과 같은 정보인 Feature를 제거한다.
   - **Encoding**: male/female 같은 범주형 데이터를 숫자로 바꾼다.
   - **Scaling**: age, fare, income, distance처럼 범위가 다른 Feature들의 Scale을 맞춘다.
7. **Model 생성 → fit() → predict() → 평가**

**9. 회귀 평가지표 쉽게 정리**

분류에서는 Accuracy/Precision/Recall/F1을 쓰지만, 회귀는 "실제값과 예측값이 얼마나 차이 나는가"를 본다.

- **R²(결정계수)**: 모델이 데이터의 움직임을 얼마나 잘 설명했는지 보는 값. 실제값이 50, 60, 70, 80, 90이고 예측이 51, 59, 71, 81, 89면 실제 움직임과 매우 비슷하므로 R²가 높게 나올 수 있다. `ȳ`(y-bar)는 실제값의 평균, `ŷ`(y-hat)은 예측값이다. R²는 "실제-예측" 그 자체를 나타내는 오차가 아니라 모델이 전체 움직임을 얼마나 설명하는지를 본다. 보통 0~1 범위지만 실제 Test 데이터에서 모델이 매우 못하면 음수가 나올 수도 있다.
- **MSE(평균 제곱 오차)**: 실제값 10,20,30 / 예측값 12,18,33이면 오차는 -2,2,-3인데 그냥 더하면 양수/음수가 서로 지워지니까 제곱한다(4,4,9). 평균 내면 5.67이 MSE다. 오차를 제곱하므로 큰 실수에 큰 벌점을 줘서 이상치에 민감하다.
- **RMSE**: MSE에 루트를 씌운 것. MSE는 단위가 원²처럼 이상해지는데, 루트를 씌우면 다시 원래 단위(원)에 가까워진다.
- **RMSLE**: 값에 로그를 적용하고 RMSE 비슷한 계산을 한다. 큰 값의 영향을 줄이고 비율 차이를 중요하게 볼 때 사용한다. 로그를 쓰면 10, 100, 1000, 10000처럼 큰 차이가 나는 값들이 서로 가까워진다. 다만 로그를 썼다고 무조건 정규분포가 되는 건 아니다.
- **MAE(평균 절대 오차)**: 오차 -2,2,-3을 절댓값으로 만들면 2,2,3, 평균은 2.33. 오차 10이면 MAE는 10 그대로지만 MSE는 100이 되니, MAE가 실제 차이를 좀 더 직관적으로 보여준다.
- **MAPE**: 실제값 대비 몇 % 틀렸는지 계산. 실제값 100, 예측값 90이면 오차 10을 실제값 100 기준으로 봐서 10%. 단위보다 퍼센트로 보고 싶을 때 이해하기 쉽지만, 실제값이 0이면 0으로 나누게 되어 계산이 안 된다.
- **sMAPE**: MAPE의 단점을 보완하려는 방식으로, 분모에 실제값만이 아니라 실제값+예측값을 함께 사용해서 과대/과소 예측을 좀 더 대칭적으로 본다.

| Metric | 한 줄 설명 |
|---|---|
| R² | 모델이 전체 움직임을 얼마나 잘 따라갔나 |
| MSE | 틀린 만큼 제곱해서 크게 혼냄 |
| RMSE | MSE가 너무 커져서 다시 루트 씌움 |
| RMSLE | 큰 숫자를 줄여놓고 RMSE 계산 |
| MAE | 얼마나 틀렸는지 절댓값으로 평균 |
| MAPE | 몇 % 틀렸는지 계산 |
| sMAPE | MAPE를 조금 더 균형 있게 계산 |

**핵심 정리**

- **Encoding**: 문자 → 숫자
- **Scaling**: 큰 숫자/작은 숫자의 Scale을 맞춤
- **fit**: 공부
- **transform**: 배운 규칙으로 데이터 바꾸기
- **predict**: 문제 풀기
- **Train**: 문제집
- **Test**: 시험지

결국 머신러닝은 "문제집으로 공부 → 시험 문제 풀기 → 정답과 비교"의 흐름이다.

```python
model.fit(x_train_features, y_train_target)      # 공부
y_pred = model.predict(x_test_features)            # 시험 문제 풀기
accuracy_score(y_test_target, y_pred)               # 채점
```
> 0.7932960893854749
