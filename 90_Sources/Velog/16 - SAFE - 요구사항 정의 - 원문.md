### [플레이데이터 SK네트웍스 Family AI 캠프 36기] 1st 프로젝트 - 요구사항 정의

드디어 첫 번째 팀 프로젝트 조가 꾸려졌다. 처음 받은 주제는 "전국 자동차 등록현황 및 FAQ"였는데, 우리 팀(3팀)은 여기에 **고령화·교통사고·미래전망** 요소를 엮어서 주제를 다시 구체화했다. 크롤링/DB 연습을 겸하는 교과목실습 단계라 데이터 수집·전처리부터 직접 해야 해서, 본격적인 개발에 들어가기 전에 요구사항정의서(v1.2)를 먼저 정리하는 시간을 가졌다.

<br>

**📌 프로젝트 주제**

> 전국 자동차 등록·고령화·교통사고 통합 분석 및 미래전망 시스템

<br>

**1. 프로젝트 개요**

**목적**

지역별로 흩어져 있는 자동차 등록 현황, 고령화, 고령운전자 교통사고, 장래인구, 운전면허/면허반납 정책 데이터를 하나로 모아서 **현재와 미래의 지역 자동차·교통환경을 조회·비교**할 수 있게 하고, 이를 통해 정부·지자체의 정책 의사결정을 지원하는 게 이번 프로젝트의 목적이다.

**배경**

> - 자동차 등록·인구·고령화·교통사고·운전면허·정책 데이터가 서로 다른 기관/시스템에 흩어져 있어서, 지역 단위로 종합 분석을 하려면 매번 따로 수집·가공해야 하는 불편함이 있었다.
- 현재 현황만 보여주는 걸 넘어서 **장래인구 전망**까지 함께 보여줘야 정책 수요를 미리 판단하는 데 도움이 된다고 판단했다.
- 그래서 공공데이터·공식 통계를 수집·정제해서 MySQL에 저장하고, Python(Streamlit) 기반으로 통합 대시보드·지역 비교·미래전망·보고서 기능을 제공하는 구조로 잡았다.
- 나중에 API 연동으로 기관 시스템까지 확장할 수 있는 구조도 염두에 두고 설계했다.

**범위**

| 범위 | 내용 |
|---|---|
| ① | 지역·연도·차종별 자동차 등록 현황 조회·시각화 |
| ② | 지역별 고령인구·고령운전자·운전면허 현황 및 2030/2035 장래인구 전망 분석 |
| ③ | 지역별 고령운전자 교통사고·사고유형·심각도 조회 및 비교 |
| ④ | 면허 자진반납 인원·반납률 및 관련 정책 조회·비교 |
| ⑤ | 등록·고령화·사고·미래전망 결합한 지역 종합분석 및 지역 간 비교 |
| ⑥ | 통합 Dashboard, 분석 Report 및 데이터 다운로드 |
| ⑦ [확장] | API를 통한 정부·지자체 내부 시스템 연동 |
| ⑧ [후순위] | 자동차 기업 FAQ 및 Groq 기반 자연어 FAQ 질의 |

처음엔 등록현황+FAQ 정도로만 생각했는데, 논의를 거치면서 범위가 꽤 넓어졌다. 다만 ⑦, ⑧번은 확장/후순위로 명시해둬서 MVP 범위가 무한정 커지지 않도록 선을 그어뒀다.

<br>

**2. 이해관계자**

역할을 내부/사용자/외부로 나눠서 정리했다.

> - **내부**: 기획/요구사항 담당(시장조사·Pain Point·우선순위), 데이터 수집·분석 담당(원천 데이터 조사·수집·전처리), DB/개발 담당(MySQL·ERD·쿼리·분석 로직), UI/API 담당(Streamlit 대시보드·시각화·보고서, 향후 API 설계)
- **사용자(핵심)**: 지자체 교통정책 담당자, 교통안전 담당자, 스마트도시/데이터 담당자, 중앙정부·공공기관 담당자
- **외부**: 공공데이터 제공기관(공공데이터포털 / KOSIS / TAAS / 공식기관)

핵심 사용자를 "지자체 교통정책 담당자"로 명확히 잡아둔 덕분에, 이후 기능을 정할 때 "이게 정책 담당자한테 실제로 필요한 정보인가?"를 기준으로 판단할 수 있었다.

<br>

**3. 기능적 요구사항 (RF)**

| 구분 | 요구사항명 | 상태 |
|---|---|---|
| RF-1.0 | 자동차 등록 현황 데이터 조회·시각화 | 확정 |
| RF-2.0 | 고령화·미래전망·지역 종합분석 | 확정 |
| RF-3.0 | 지역별 고령운전자 교통사고 분석 | 확정 |
| RF-4.0 | 운전면허 자진반납·정책 분석 | 확정 |
| RF-5.0 | 정부·지자체용 SaaS 서비스 (Dashboard/Report/API) | 확정 (API는 Optional) |
| RF-6.0 | [후순위] 자동차 기업 FAQ | 후순위 |
| RF-7.0 | [Optional] Groq 기반 자연어 FAQ | Optional |

각 요구사항을 좀 더 풀어보면:

- **RF-1.0 자동차 등록 현황 조회·시각화**: 공공데이터에서 지역·연도·차종·신규/말소 등록 데이터를 수집하고, 조건별로 조회·비교하고 그래프로 시각화한다.
- **RF-2.0 고령화·미래전망·지역 종합분석**: 지역별 총인구/65세 이상 인구/고령화율/고령운전자 수/면허소지자 수를 모으고, KOSIS의 2030·2035 장래인구·고령화율 데이터를 같은 기준으로 관리해서 등록·고령화·사고·미래전망을 한 화면에서 통합 조회하고 전국 평균/타 지역과 비교할 수 있게 한다. 단, **미래 사고건수는 단순 예측하지 않는다**는 원칙을 세웠다.
- **RF-3.0 지역별 고령운전자 교통사고 분석**: TAAS 등에서 지역·연도별 고령운전자 사고건수·유형·사상자·심각도를 수집해서 조건별로 조회·비교하고, 등록대수·고령운전자 수 대비 상대적 사고 수준과 연도별 추이를 시각화한다.
- **RF-4.0 운전면허 자진반납·정책 분석**: 지역별 자진반납 인원·반납률과 지원정책(정책명/시행일/대상연령/지원금)을 구축하고, 정책 시행 시점 전후로 사고건수·사고율 변화를 비교한다. 다만 정책 효과를 해석할 때 **인과관계를 단정하지 않고 분석의 한계를 함께 안내**하기로 했다.
- **RF-5.0 정부·지자체용 SaaS 서비스**: 위 지표들을 통합 Dashboard로 제공하고, 분석 결과를 보고서/데이터 파일로 다운로드할 수 있게 하며, 확장 단계에서는 API로도 제공한다.
- **RF-6.0 / RF-7.0**: 자동차 기업 FAQ 검색과 Groq 기반 자연어 FAQ 질의는 MVP 범위에서 제외하고 후순위/Optional로 남겨뒀다. 외부 API 응답시간·비용·정확성에 의존한다는 리스크도 함께 적어뒀다.

<br>

**4. 비기능적 요구사항 (NFR)**

| 구분 | 핵심 내용 |
|---|---|
| 성능 | 일반 조회 3초 이내 응답, 통합분석·보고서는 처리상태 표시 + 합리적 시간 내 제공 |
| 정확성·신뢰성 | DB 저장값과 조회·분석 결과 일치, 중복·누락 방지, 출처·기준연도·관측값/추계값 구분 표시 |
| 사용성 | 별도 분석 지식 없이 지역·연도·차종·사고유형 등으로 직관적 조회, 그래프에 제목·단위·범례·기준연도 명시 |
| 보안 | 외부 API 키·인증정보 GitHub 비노출, MySQL 접속정보 하드코딩 금지(환경변수/Secrets) |
| 유지보수성·확장성 | 코드·SQL·ERD·문서 역할별 관리 및 GitHub 형상관리, 신규 데이터·API 확장 시 기존 구조 최소 변경 |

특히 "관측값/추계값 구분 표시"를 정확성·신뢰성 항목에 못박아둔 게 인상적이었다. 장래인구 전망치를 실제 현황처럼 보여주면 오해를 살 수 있기 때문에, 그래프나 표에서부터 이 둘을 구분해서 보여줘야 한다는 걸 요구사항 단계에서부터 합의해둔 셈이다.

<br>

**5. 제약사항 및 대응방안**

| 구분 | 제약 내용 | 대응 방안 |
|---|---|---|
| 데이터 | 제공 항목·기간·갱신주기가 제공기관 정책에 의존 | 조사 단계에서 항목·기준연도 확인 후 확보 가능 범위로 기준 확정 |
| 데이터 품질 | 결측값·중복값·지역명/연도 형식 불일치 가능 | 수집 후 검증 및 지역·연도 기준 표준화 |
| 정책 데이터 | 여러 지자체·기관 자료에 분산 | 공식 자료 우선 사용, 정책 조건·기준연도 별도 관리 |
| 미래 전망 | 장래인구는 추계값, 고령화만으로 미래 사고 직접 예측 불가 | 관측값/추계값 구분 표시, 사고건수 단정 대신 변화 가능성 중심 제시 |
| 보안 | API 키·DB 비밀번호 노출 위험 | 환경변수/Secrets, .gitignore, 민감정보 커밋 금지 |
| 일정 | 다수 데이터·기능 동시 구현 시 범위 과다 | 등록·고령화/미래·사고·종합분석을 MVP 핵심으로, API·FAQ는 단계적 적용 |
| 분석 해석 | 정책 전후 변화를 정책만의 효과로 단정 불가 | 상관관계는 제공하되 인과관계 단정 표현 제한, 분석 한계 명시 |

<br>

**6. 기대 효과**

> **긍정적 효과**
- 등록·고령화·사고·면허반납·미래전망을 지역 기준으로 통합 조회할 수 있어서 여러 기관 데이터를 따로 찾아다니는 시간을 줄일 수 있다.
- 현재 현황과 2035년 전망을 함께 확인하고 보고서까지 생성할 수 있으며, 향후 API로 기관 내부 시스템에서도 활용할 수 있다.

> **한계 및 대응**
- 데이터 제공범위·정책 정보·장래 추계의 한계 때문에 일부 지역 비교나 미래 해석이 제한될 수 있다.
- 이에 대해 출처·기준연도·추계 여부를 명시하고, 분석의 한계를 함께 안내하기로 했다.

<br>
