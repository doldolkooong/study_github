**1. Git 설치 및 설정**

가장 먼저 Git을 설치했다. Git은 소스 코드를 효율적으로 관리하고 변경 이력을 기록할 수 있는 버전 관리 시스템으로, 개발 프로젝트에서는 필수적으로 사용되는 도구이다. 또한 팀원들과 코드를 공유하고 협업하는 과정에서도 중요한 역할을 하기 때문에, 앞으로 진행될 실습과 프로젝트를 위해 가장 먼저 설치하였다.

설치 사이트 - <https://git-scm.com/>
설치 후 git bash에 접속하여 아래 코드들을 작성한다.

- git 버전 확인
``` bash
$ git --version

(실행결과) git version 2.55.0.windows.3

```

- git에서 사용자 이름 및 메일 설정
```bash
$ git config --global user.name "(내 이름)"
$ git config --global user.email "(내 이메일)"
```

- 설정한 모든 것 확인 가능
```bash
$ git config --list

core.autocrlf=true
core.fscache=true
core.symlinks=false
pull.rebase=false
credential.helper=manager
init.defaultbranch=main
core.editor=code
```

설치 사이트 - <https://www.python.org/downloads/>

설치할 때 PATH 설정할 거냐는 것에 체크표시를 꼭 해야한다. 안 하게 되면 환경변수 설정하러 가야하는 복잡한 과정을 거쳐야 한다..

- 설치된 파이썬 버전 확인 
```bash
$ python --version
Python 3.13.15
```

버전 표기 규칙: 3(메이저) . 13(마이너) . 15(패치/수정)

**4. 개발자 폴더 생성**

다음으로 개발에 사용할 작업 공간을 구성하기 위해 C드라이브에 dev 폴더를 생성하였다. dev는 develop의 약자로, 앞으로 진행할 학습과 프로젝트를 체계적으로 관리하기 위한 최상위 작업 폴더이다.

dev 폴더 내부에는 용도에 따라 다음과 같이 하위 폴더를 구성하였다.

* course : 부트캠프에서 제공하는 강의 자료를 보관하는 폴더이다. 원본 자료의 훼손을 방지하기 위해 수정, 조회, 실행은 하지 않고 보관 용도로만 사용한다.
* study : 강의 내용을 직접 실습하고 복습하며 학습한 내용을 정리하는 폴더이다.
* project : 개인 프로젝트와 팀 프로젝트를 진행하며 개발 결과물을 관리하는 폴더이다.

이처럼 폴더를 목적에 맞게 분리하여 관리함으로써 강의 자료와 실습 코드, 프로젝트를 체계적으로 관리할 수 있는 개발 환경을 구성하였다.

>C:\dev
 ├─ course   # 강의자료 (수정·조회·실행 금지, 원본 보존용)
 ├─ study    # 공부용 작업 폴더
 └─ project  # 프로젝트 폴더
 
**5. 강의 자료 다운**

>ctrl + shift + p
git: clone

개발 환경 구성이 끝난 후에는 Git을 이용하여 강의자료를 다운로드하였다. Visual Studio Code에서 **Ctrl + Shift + P**를 눌러 명령 팔레트를 실행한 뒤 Git: Clone 명령을 선택하여 강의자료 저장소를 복제하였다. 이후 다운로드 위치를 앞서 생성한 course 폴더로 지정하여 강의자료를 저장하였다.

Git을 통해 저장소를 복제하면 강의자료를 체계적으로 관리할 수 있으며, 추후 변경 사항이 있을 경우에도 최신 자료를 손쉽게 받아올 수 있다는 장점이 있다.

**6. powershell 설정**

일부 PowerShell 스크립트가 정상적으로 실행될 수 있도록 PowerShell을 관리자 권한으로 실행한 후 실행 정책(Execution Policy)을 확인하고 변경하였다.

* 현재 실행 정책을 확인
```bash
PS> Get-ExecutionPolicy
Restricted
```

* 실행 정책을 RemoteSigned로 설정
```bash
PS> Set-ExecutionPolicy RemoteSigned
신뢰하지 않는 스크립트로부터 보호하는 정책이므로 변경 시 경고가 뜸 → Y 입력
```

* 설정 잘 바뀌었는지 확인
```bash
PS> Get-ExecutionPolicy
RemoteSigned
```

* RemoteSigned : 로컬에서 직접 작성한 스크립트는 자유롭게 실행할 수 있으며, 인터넷에서 다운로드한 스크립트는 신뢰할 수 있는 서명이 있는 경우에만 실행할 수 있도록 하는 설정


**7. UV 설치**
다음으로 Python 패키지와 가상환경을 효율적으로 관리하기 위해 UV를 설치하였다. UV는 Python 패키지 관리자와 가상환경 관리 기능을 제공하는 도구로, 기존 pip보다 빠른 설치 속도와 높은 성능을 제공하여 최근 Python 개발 환경에서 많이 사용되고 있다.

설치가 완료된 후에는 안내 메시지와 함께 실행 파일이 정상적으로 설치되었음을 확인하였다. 이후 uv --version 명령어를 실행하여 설치 여부를 확인한 결과, uv 0.12.2가 정상적으로 출력되어 설치가 완료되었음을 확인하였다.

앞으로는 UV를 이용하여 Python 버전 관리, 가상환경 생성 및 패키지 설치를 보다 빠르고 효율적으로 수행할 예정이다.

```bash
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

$ uv --version
uv 0.12.2
```

학부생 때는 Python 패키지를 설치하거나 관리할 때 항상 pip만 사용했기 때문에, 이번에 처음 접한 UV가 상당히 인상적이었다. 기존에는 pip가 가장 익숙한 도구라고 생각했는데, 강의를 통해 UV가 패키지 설치뿐만 아니라 Python 버전 관리와 가상환경 관리까지 지원하는 최신 도구라는 점을 알게 되었다. 앞으로 부트캠프를 진행하면서 UV를 직접 사용해 보며 기존 pip와 어떤 차이가 있는지 경험해 보고, 새로운 개발 도구에도 빠르게 적응해 나가야겠다는 생각이 들었다.


**8. WSL 설치**
다음으로 Windows에서도 Linux 개발 환경을 사용할 수 있도록 WSL(Windows Subsystem for Linux)을 설치하였다. WSL은 Windows 운영체제에서 별도의 듀얼 부팅이나 가상 머신 없이 Linux 환경을 사용할 수 있도록 지원하는 기능으로, AI 및 백엔드 개발 환경에서 자주 활용된다고 한다.

* WSL 2.7.11 설치
```bash
PS> C:\WINDOWS\system32> wsl --install

다운로드 중: Linux용 Windows 하위 시스템 2.7.11
설치 중: Linux용 Windows 하위 시스템 2.7.11
Linux용 Windows 하위 시스템 2.7.11이(가) 설치되었습니다.
작업을 완료했습니다.
다운로드 중: Ubuntu
설치 중: Ubuntu
배포가 설치되었습니다. 'wsl.exe -d Ubuntu'을(를) 통해 시작할 수 있습니다.
Ubuntu 시작하는 중...
Provisioning the new WSL instance Ubuntu
This might take a while...
Create a default Unix user account: administrator
```
PowerShell을 관리자 권한으로 실행한 후 wsl --install 명령어를 실행하여 WSL과 Ubuntu를 함께 설치하였다. 설치가 완료된 후 Ubuntu를 처음 실행하여 기본 사용자 계정을 생성하고 비밀번호를 설정하였다.

(다른 분들은 우분투 설치한다고 안 나온 거 같은데 나는 한번에 같이 설치가 되었다...)


* WSL 설치 잘 되었는지 확인
```bash
PS C:\WINDOWS\system32> wsl --version

WSL 버전: 2.7.11.0
커널 버전: 6.18.33.2-2
WSLg 버전: 1.0.73.2
MSRDC 버전: 1.2.7214
Direct3D 버전: 1.611.1-81528511
DXCore 버전: 10.0.26100.1-240331-1435.ge-release
Windows 버전: 10.0.26200.8973

```

```bash
PS C:\WINDOWS\system32> wsl --set-default-version 2

# 신규 배포판을 WSL2로 강제 설정

```
wsl --set-default-version 2 명령어를 실행하여 기본 버전을 WSL 2로 설정하였다. WSL 2는 실제 Linux 커널을 기반으로 동작하기 때문에 WSL 1보다 성능과 호환성이 뛰어나며, Docker와 AI 개발 환경에서도 사용할 수 있게 되었다.
