# 1st 프로젝트 - 데이터 분석 및 검증

<br>

이전 단계에서 공공데이터를 전처리하고 데이터베이스에 적재했다. 하지만 DB에 데이터가 정상적으로 들어갔다고 해서 바로 웹 서비스를 구현할 수 있는 건 아니었다. 실제 웹 구현에 들어가기 전에 다음과 같은 부분을 먼저 확인해야 했다.

> - 전처리한 데이터에 이상값이나 누락된 값은 없는가?
- 숫자와 날짜가 분석 가능한 자료형으로 저장되었는가?
- 지역·연도·연령·시간대별 집계가 정상적으로 이루어지는가?
- 데이터에서 실제로 의미 있는 추세를 확인할 수 있는가?
- 어떤 지표와 그래프를 웹 대시보드에 제공할 것인가?
- 현재 데이터로 향후 예측까지 가능한가?

그래서 본격적인 웹 구현 전에 pandas로 탐색적 데이터 분석(EDA)을 수행해서 데이터의 상태와 분석 가능성을 먼저 검증했다. 전체 과정은 다음과 같이 진행했다.

```text
전처리 데이터
      ↓
DB 적재
      ↓
pandas로 데이터 조회
      ↓
자료형 및 데이터 구조 확인
      ↓
필터링 / 그룹화 / 집계
      ↓
Matplotlib 기반 시각화
      ↓
분석 결과 및 데이터 이상 여부 확인
      ↓
웹 대시보드 적용 항목 결정
```

<br>

**1. 데이터 분석 전 검증**

먼저 데이터베이스에 저장된 데이터를 pandas DataFrame으로 불러왔다.

```python
with sqlite3.connect("database/accident.db") as conn:
    df = pd.read_sql(
        "SELECT * FROM old_driver_region_time",
        conn
    )
```

이후 분석에 사용할 컬럼의 자료형을 다시 확인했다.

```python
df["year"] = pd.to_numeric(df["year"])
df["month"] = pd.to_numeric(df["month"])
df["accidents"] = pd.to_numeric(df["accidents"])
```

실제 고령운전자 지역별 사고 분석에서도 연도, 월, 사고건수를 숫자형으로 변환한 뒤 분석을 진행했다. 단순히 DB 적재 성공 여부만 확인하는 게 아니라, 실제 `groupby`, 필터링, 시계열 분석 등에 바로 쓸 수 있는 상태인지 다시 확인하는 과정이었다.

<br>

**2. 인구 데이터 분석**

인구 데이터에서는 먼저 지역별 인구와 연도별 인구 변화가 정상적으로 나타나는지 확인했다. 지역별 인구 데이터는 기존 Wide 형태를 분석하기 쉬운 Long 형태로 다시 변환했다.

```python
long_df = df.melt(
    id_vars="region",
    value_vars=pop_cols,
    var_name="year",
    value_name="population"
)
```

이를 통해 하나의 `year` 컬럼을 기준으로 연도별 데이터를 분석할 수 있도록 했다. 이후 `groupby()`로 연도별 전국 인구를 집계했다.

```python
yearly = (
    long_df
    .groupby("year", as_index=False)["population"]
    .sum()
)
```

또 2021년과 2025년 인구를 비교해서 지역별 증감량과 증감률도 계산했다.

```python
change["증감"] = (
    change["population_2025"]
    - change["population_2021"]
)

change["증감률"] = (
    change["증감"]
    / change["population_2021"]
    * 100
)
```

이를 통해 단순히 인구수를 보여주는 것뿐 아니라, 지역별 인구 변화율까지 웹에서 제공할 수 있는지 확인했다. 주민등록 인구 데이터에서는 월별 컬럼을 `year, month, date, population` 구조로 변환해 월별 시계열 분석 가능 여부도 확인했다.

<br>

**3. 자동차·운전면허 데이터 분석**

자동차 데이터에서는 다음과 같은 항목을 중심으로 확인했다.

> - 연도별 자동차 등록 추세
- 차종별 자동차 등록 현황
- 용도별 자동차 등록 현황
- 지역별 자동차 등록 현황
- 연령별 운전면허 보유 현황
- 지역별 운전면허 보유 현황
- 65세 이상 운전면허 보유 추세
- 운전면허 자진반납 현황

자동차 등록 데이터는 `year`, `vehicle_type`을 기준으로 그룹화해서 차종별 등록대수 변화가 정상적으로 나타나는지 확인했다.

```python
trend = (
    df.groupby(
        ["year", "vehicle_type"],
        as_index=False
    )["count"]
    .sum()
)
```

지역 데이터에서는 시도와 시군구를 결합해서 같은 이름을 가진 중구, 서구 등이 서로 다른 지역으로 처리되도록 했다.

```python
df["region"] = df["sido"] + " " + df["sigungu"]
```

운전면허 데이터에서는 나이, 연도, 면허 종류별 분포를 확인하고 65세 이상만 별도로 필터링했다.

```python
old_df = df[
    df["age"] >= 65
].copy()
```

이를 통해 고령운전자 면허 보유 추세를 별도로 분석할 수 있는지 검증했다.

<br>

**4. 운전면허 자진반납 데이터 분석**

고령운전자 정책과 연결하기 위해 운전면허 자진반납 데이터도 별도로 분석했다. 2023년 데이터에서는

> - 지역별 자진반납
- 연령별 자진반납
- 지역 × 연령 분포
- 65세 이상 자진반납
- 자진반납 연령 TOP 10

등을 확인했다. 여기서도 고령운전자 기준인 65세 이상만 필터링했다.

```python
old_df = df[
    df["age"] >= 65
].copy()
```

그리고 `groupby()`와 `sort_values()`로 반납이 많은 연령대를 확인했다.

```python
age_rank = (
    df.groupby("age", as_index=False)["count"]
    .sum()
    .sort_values("count", ascending=False)
    .head(10)
)
```

이를 통해 향후 웹에서 지역별 자진반납 규모와 고령운전자 연령별 반납 분포를 비교할 수 있는지 확인했다.

<br>

**5. 교통사고 데이터 분석**

교통사고 데이터는 SAFE 서비스의 핵심 데이터이기 때문에 가장 다양한 기준으로 분석을 진행했다.

> - 연령대별 사고 / 연도별 사고 / 시간대별 사고
- 기상상태별 사고 / 지역별 사고 / 월별 사고
- 지역 × 월 / 연령 × 시간대 / 월 × 시간대

시간대 데이터는 기존 Wide 구조를 `melt()`로 Long 구조로 변경했다.

```python
df = df.melt(
    id_vars="age_group",
    var_name="time_slot",
    value_name="accidents"
)
```

그리고 `time_00_02` 같은 값을 `00~02` 형태로 변환했다. 이를 통해 연령대별·시간대별 사고를 히트맵으로 비교할 수 있는지 확인했다.

**지역 × 월**

고령운전자 사고 데이터에서는 시도·시군구·연도·월을 이용해 지역별 사고 패턴을 확인했다.

```python
monthly = (
    df.groupby("month", as_index=False)["accidents"]
    .sum()
    .sort_values("month")
)
```

여기서도 같은 이름의 시군구가 중복되지 않도록 시도와 시군구를 결합했다. 이를 기반으로 시도별·월별 히트맵까지 생성해서 특정 지역에서 특정 월에 사고가 집중되는지 시각적으로 확인할 수 있도록 테스트했다.

**기상상태별 사고**

기상 데이터에서는 연령대를 기준으로 데이터를 나눈 뒤 `groupby()`로 날씨별 사고건수를 집계했다.

```python
weather = (
    age_df
    .groupby("weather", as_index=False)["accidents"]
    .sum()
    .sort_values("accidents", ascending=False)
)
```

`year × weather` 기준으로도 다시 집계해서 기상상태별 사고 변화를 확인했다.

<br>

**6. 정책 데이터 분석**

정책 데이터 중 교통안전교육 데이터는 실제 수치 분석이 가능한 데이터라 월별 교육 정원을 중심으로 분석했다. 먼저 교육 날짜에서 월 정보를 추출했다.

```python
df["month"] = (
    df["edu_date"]
    .dt.to_period("M")
    .dt.to_timestamp()
)
```

그리고 월별 교육 정원을 집계했다.

```python
monthly = (
    df.groupby("month", as_index=False)["capacity"]
    .sum()
)
```

추가로 월별 전체 교육 정원, 과정별 월별 교육 정원, 교육장별 월별 교육 정원, 월별 평균 교육 정원을 분석해서 정책 데이터 역시 웹에서 통계 형태로 제공할 수 있는지 확인했다.

<br>

**7. 시각화를 통한 데이터 검증**

이번 단계에서 그래프를 만든 목적은 최종 대시보드를 완성하는 게 아니었다. 전처리한 데이터가 실제로 분석 가능한 형태인지 빠르게 확인하기 위해 Matplotlib과 공통 시각화 함수를 사용했다. 주로 다음 세 가지 형태를 활용했다.

| 시각화 | 확인 목적 |
|---|---|
| Line Plot | 연도·월별 변화와 추세 확인 |
| Bar Plot | 지역·연령·차종 등 항목 간 규모 비교 |
| Heatmap | 지역×월, 연령×시간대 등 두 변수 관계 확인 |

예를 들어 운전면허 데이터에서는 지역 × 연도를 히트맵으로 확인하고, 지역별 연도 변화도 별도로 집계했다. 즉 이 단계의 시각화는 서비스용 최종 시각화라기보다, **데이터와 분석 로직을 검증하기 위한 프로토타입**에 가까웠다.

<br>

**8. 미래 예측 가능 여부 테스트**

SAFE는 현재 현황뿐 아니라 향후 고령운전자 사고 추세도 제공하고자 했기 때문에 시계열 분석이 가능한지도 테스트했다. 고령운전자 월별 사고 데이터에서는

```python
monthly = (
    df.groupby(
        ["year", "month"],
        as_index=False
    )["accidents"]
    .sum()
)
```

으로 월별 시계열을 만든 뒤 날짜 컬럼을 생성했다. 이후 별도로 구현한 `forecast_best()`를 이용해 ARIMA, SARIMA, Prophet 등의 시계열 모델을 비교하고, 적합한 모델로 미래 데이터를 예측할 수 있는지도 테스트했다. 실제 월별 고령운전자 사고 데이터에서는 미래 12개월 예측을 호출하도록 구성했다. 연령대별 사고에서도 실제 데이터를 피벗 테이블로 먼저 확인한 뒤 예측 로직으로 이어지는 구조를 사용했다.

<br>

**9. 분석 및 검증 결과**

이번 단계의 핵심은 정교한 통계 분석 결과를 만드는 게 아니라, **전처리한 데이터가 실제 서비스에 활용 가능한지를 확인하는 것**이었다.

```text
데이터 전처리
      ↓
DB 적재
      ↓
분석용 DataFrame 조회
      ↓
자료형 / 구조 검증
      ↓
필터링
      ↓
groupby / pivot / 집계
      ↓
Matplotlib 시각화
      ↓
시계열 분석 테스트
      ↓
웹 구현 가능 여부 확인
```

분석을 진행하면서 다음과 같은 기능들을 실제 데이터로 구현할 수 있음을 확인했다.

> - 지역별·연도별 인구 변화
- 자동차 등록대수 및 차종별 변화
- 연령·지역별 운전면허 보유 현황
- 고령운전자 면허 자진반납 현황
- 연령·시간대·지역·기상조건별 교통사고 분석
- 고령운전자 교통안전교육 현황
- 교통사고 시계열 기반 미래 추세 예측

따라서 이후 웹 구현에서는 이번 단계에서 검증한 분석 로직을 기반으로 Streamlit과 Plotly를 이용해, 사용자가 지역·연도·연령 등의 조건을 직접 선택할 수 있는 대시보드 형태로 구현하기로 했다.

이번 과정을 통해 데이터 전처리가 끝났다고 바로 서비스 구현으로 넘어가기보다는, 실제 분석을 먼저 수행해서 데이터가 의도한 질문에 답할 수 있는지 확인하는 과정이 필요하다는 걸 알게 됐다.
