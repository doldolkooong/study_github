## 1단원 — 핵심 정의 🟢 ⭐

### ① 무엇인가?

Docker의 MySQL에 클라이언트로 연결하고 기본키·자동 채번이 있는 테이블을 구성한다.

### ② 왜 필요한가?

컨테이너 실행 상태와 노출 포트를 확인한다. 테이블을 정의하고 데이터를 넣은 후 키·행을 조회해 확인한다. 이를 통해 실행 환경에서 자동 채번까지 연결해 이해한다.

### ③ 쉽게 이해하기 🎨

> [!example] 비유
> 창고 서버에 접속한 뒤 같은 번호가 중복되지 않는 물품 대장을 만든다.

### ④ 핵심 용어

| 용어 | 뜻과 적용 포인트 |
|---|---|
| 실행 환경 | Docker는 DB가 실행되는 환경이고 DBeaver는 접속·조회 클라이언트다. |
| 연결 문제 | 호스트·포트·계정·인증 오류를 구분해 확인한다. |
| 스키마 | 테이블과 컬럼의 타입·주석·제약을 정의한다. |
| 기본키 | PRIMARY KEY는 행 식별에 쓰이고 중복·NULL을 허용하지 않는다. |
| 자동 채번 | AUTO_INCREMENT는 식별 번호를 자동 생성하지만 빈틈 없는 순번을 보장하는 기능은 아니다. |

## 2단원 — 원리 / 동작 과정 🔵 ⭐

### ① 전체 흐름

1. 컨테이너 실행 상태와 노출 포트를 확인한다.
2. 대상 DB·사용자·인증 설정으로 연결한다.
3. 테이블을 정의하고 데이터를 넣은 후 키·행을 조회해 확인한다.

### ② 왜 이렇게 동작하는가?

호스트·포트·계정·인증 오류를 구분해 확인한다. AUTO_INCREMENT는 식별 번호를 자동 생성하지만 빈틈 없는 순번을 보장하는 기능은 아니다.

## 3단원 — 코드 / 공식 🔵 ⭐

### ① 핵심 코드

> 아래는 원문의 개념을 작은 입력으로 재구성한 학습용 예제다. 원문 코드는 하단 원문에서 확인할 수 있다.

```sql
CREATE TABLE study_example (
  id INT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(50) NOT NULL
);
INSERT INTO study_example (name) VALUES ('alpha'), ('beta');
SELECT id, name FROM study_example ORDER BY id;
```

### ② 코드 이해

| 읽는 순서 | 의미 |
|---|---|
| 입력과 전제 | 컨테이너 실행 상태와 노출 포트를 확인한다. |
| 처리 | 대상 DB·사용자·인증 설정으로 연결한다. |
| 결과 | 설명용 SQL이며 실제 DB 생성·삭제·삽입은 하지 않았다. |

### ③ 실행 결과

**예상 결과·해석 기준 — 실제 환경 실행 결과와 구분**

```text
비어 있는 새 테이블을 기본 설정으로 만들었다면 alpha·beta에 자동 생성된 id가 붙는다.
```

### ④ 결과 해석

설명용 SQL이며 실제 DB 생성·삭제·삽입은 하지 않았다.
