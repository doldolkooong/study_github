## 1단원 — 핵심 정의 🟢 ⭐

### ① 무엇인가?

표준화한 DataFrame을 테이블 구조와 연결하고 적재 결과를 조회로 확인한다.

### ② 왜 필요한가?

DataFrame 컬럼과 자료형을 DB 스키마에 맞춘다. DB를 다시 조회해 원본 행 수·키·집계와 대조한다. 이를 통해 입력 표준화에서 적재 검증까지 연결해 이해한다.

### ③ 쉽게 이해하기 🎨

> [!example] 비유
> 정리된 서류를 분류 기준이 같은 서랍에 넣고 수량을 대조한다.

### ④ 핵심 용어

| 용어 | 뜻과 적용 포인트 |
|---|---|
| 입력 표준화 | 병합 셀·숫자 문자열·다중 헤더·총계 행을 처리한다. |
| 테이블 구조 | 인구·차량·사고·정책·FAQ를 분석 목적에 맞는 테이블로 나눈다. |
| 연결 계층 | pandas 데이터와 MySQL 사이에 SQLAlchemy·PyMySQL을 사용한다. |
| 적재 설정 | 컬럼 타입, index 저장 여부, 재실행 시 중복·교체 정책을 확인한다. |
| 적재 검증 | 성공 메시지뿐 아니라 테이블의 행 수·컬럼·키·집계 결과를 비교한다. |

## 2단원 — 원리 / 동작 과정 🔵 ⭐

### ① 전체 흐름

1. DataFrame 컬럼과 자료형을 DB 스키마에 맞춘다.
2. 연결 설정을 분리하고 정한 적재 정책에 따라 저장한다.
3. DB를 다시 조회해 원본 행 수·키·집계와 대조한다.

### ② 왜 이렇게 동작하는가?

인구·차량·사고·정책·FAQ를 분석 목적에 맞는 테이블로 나눈다. 성공 메시지뿐 아니라 테이블의 행 수·컬럼·키·집계 결과를 비교한다.


## 3단원 — 코드 / 공식 🔵 ⭐

### ① 핵심 코드

> 아래는 원문의 개념을 작은 입력으로 재구성한 학습용 예제다. 원문 코드는 하단 원문에서 확인할 수 있다.

```sql
SELECT region, year, COUNT(*) AS row_count
FROM local_population
GROUP BY region, year
HAVING COUNT(*) > 1;
```

### ② 코드 이해

| 읽는 순서 | 의미 |
|---|---|
| 입력과 전제 | DataFrame 컬럼과 자료형을 DB 스키마에 맞춘다. |
| 처리 | 연결 설정을 분리하고 정한 적재 정책에 따라 저장한다. |
| 결과 | local_population의 한 행이 지역·연도별 인구라는 가정의 검증 쿼리다. 실제 DB 연결과 실행은 하지 않았다. |

### ③ 실행 결과

**예상 결과·해석 기준 — 실제 환경 실행 결과와 구분**

```text
지역·연도가 유일키인 테이블이라면 중복 후보가 있는 키만 반환한다.
```

### ④ 결과 해석

local_population의 한 행이 지역·연도별 인구라는 가정의 검증 쿼리다. 실제 DB 연결과 실행은 하지 않았다.

## 🔧 디버깅 포인트

| 증상 | 원인 | 해결 |
|---|---|---|
| 다시 적재하니 행 수가 증가 | append의 중복 처리 전략 없음 | 유일키·upsert·적재 이력을 설계 |
| 인덱스가 불필요한 DB 컬럼으로 저장 | DataFrame 인덱스와 업무 키를 혼동 | 저장할 컬럼과 index 옵션을 확인 |
