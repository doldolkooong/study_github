## 1단원 — 핵심 정의 🟢 ⭐

### ① 무엇인가?

요구사항을 구현할 데이터의 출처·항목·단위·키·미확정 사항을 명세한다.

### ② 왜 필요한가?

기능 요구사항마다 필요한 정보와 원천 기관을 정한다. 결합 가능성과 누락 항목을 확인하고 문서·ERD·전처리에 연결한다. 이를 통해 5대 카테고리에서 미확정 범위까지 연결해 이해한다.

### ③ 쉽게 이해하기 🎨

> [!example] 비유
> 요리 전에 재료 목록과 원산지·단위·필요량을 정하는 단계다.

### ④ 핵심 용어

| 용어 | 뜻과 적용 포인트 |
|---|---|
| 5대 카테고리 | 인구, 자동차, 교통사고, 교통법규·정책, FAQ를 식별했다. |
| 추적 가능성 | 데이터 묶음이 어떤 RF 요구사항에 대응하는지 기록한다. |
| 공통 기준 | 지역·연도를 연결 기준으로 삼되 시간·연령·지역 세분화 수준을 함께 맞춘다. |
| 항목 명세 | 이름·형식·필수 여부·예시·허용 범위·출처를 적는다. |
| 미확정 범위 | 정의 당시 FAQ는 수집 예정이었고 후속 글에서 전처리·웹 구현으로 이어졌다. |

## 2단원 — 원리 / 동작 과정 🔵 ⭐

### ① 전체 흐름

1. 기능 요구사항마다 필요한 정보와 원천 기관을 정한다.
2. 컬럼·자료형·단위·관측 주기·지역 기준을 정의한다.
3. 결합 가능성과 누락 항목을 확인하고 문서·ERD·전처리에 연결한다.

### ② 왜 이렇게 동작하는가?

데이터 묶음이 어떤 RF 요구사항에 대응하는지 기록한다. 정의 당시 FAQ는 수집 예정이었고 후속 글에서 전처리·웹 구현으로 이어졌다.

### ③ 그림으로 설명


## 3단원 — 코드 / 공식 🔵 ⭐

### ① 핵심 코드

> 아래는 원문의 개념을 작은 입력으로 재구성한 학습용 예제다. 원문 코드는 하단 원문에서 확인할 수 있다.

```text

연결: 자동차·사고 표도 같은 지역·연도 수준으로 먼저 집계
```
